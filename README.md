# OLED Measurement App

Версия: `v2.0.0-alpha`

Приложение для ведения серий измерений OLED-пикселей: ВАЯХ/IVL, спектры, стабильность, журнал серии и экспорт данных в Excel.

`v2.0.0-alpha` накапливает переход к отдельной FastAPI/React/WebView2-оболочке.
Зафиксировано поведение `v1.9.1`, а технический прототип уже собирается в
автономный `onedir`, открывается в собственном WebView2-окне и выполняет
simulator-first PoC SMU/спектрометра с live-графиком и безопасной остановкой.
Stage 3 добавляет общую дизайн-систему и эталон будущего экрана серии. Рабочий
Tkinter-интерфейс по-прежнему запускается через `oled_modular_app.py` и остаётся
штатным приложением до завершения функциональной и аппаратной проверки. Все
следующие этапы обновляют тот же prerelease и тег `v2.0.0-alpha`.

## Быстрый Запуск

Новый модульный GUI:

```powershell
.\env\Scripts\python.exe .\oled_modular_app.py
```

Референсное приложение остается доступным для сравнения поведения:

```powershell
.\env\Scripts\python.exe .\oled_measurement_app_v2_5.py
```

Проверка нового входа без открытия GUI:

```powershell
.\env\Scripts\python.exe .\oled_modular_app.py --status
```

Отдельный технический прототип v2:

```powershell
.\env\Scripts\python.exe .\oled_v2_app.py --status
.\env\Scripts\python.exe .\oled_v2_app.py --backend-smoke
.\env\Scripts\python.exe .\oled_v2_app.py --poc-smoke
.\env\Scripts\python.exe .\oled_v2_app.py
```

В окне v2 кнопка `Запустить эмулятор` выполняет короткий sweep без записи
измерительных файлов, `Безопасно остановить` отключает оба выхода SMU, а
`Проверить приборы` делает пассивный probe текущих настроек. Активный тест
реального стенда пока не включён.

Пункт `Серия` открывает эталон Stage 3: фильтры, таблицу пикселей, статусы,
график, уведомление и пример безопасного диалога. Это только визуальный контракт
для Stage 4 — пользовательские серии и файлы не открываются и не изменяются.

Тестовая `onedir`-сборка создаётся командой:

```powershell
.\scripts\build_v2_alpha.ps1
```

Если окружение нужно создать заново:

```powershell
py -3 -m venv env
.\env\Scripts\python.exe -m pip install -r requirements.txt
.\env\Scripts\python.exe -m pip install -r requirements-v2.txt
```

## Камера Canon

На экране выбора серии кнопка `Свободная камера` открывает прежний независимый режим с произвольными именами и выбором файлов Raspberry Pi. В меню открытой серии кнопка `Камера серии` требует выбрать станцию `ВАЯХ`/`Стабильность` и пиксель из журнала:

- подключение к сервису и проверка `gphoto2`;
- открытие параметров и запуск выбранного режима ВАЯХ или стабильности для выбранного пикселя;
- LiveView без VNC Viewer;
- сохранение текущего preview-кадра;
- полноразмерное фото;
- собственное название для кадра LiveView или полноразмерного фото без ручного ввода расширения `.jpg`;
- запись LiveView-потока в MP4;
- выбор доступного подключённой камерой JPEG-качества фото;
- выбор ISO, выдержки, диафрагмы и экспокоррекции после опроса доступных для записи параметров камеры;
- раздельный выбор качества/размера и FPS LiveView, если подключённая камера действительно предоставляет такие параметры; недоступные строки полностью скрываются;
- показ фактического разрешения и FPS потока без искусственного изменения частоты в FFmpeg;
- выбираемое создание отдельной копии видео стабильности с уставкой напряжения и измеренным током на добавленной верхней полосе;
- произвольный центральный кроп по ширине и высоте от 1 до 100%, применяемый к предпросмотру, снимкам и видео;
- скачивание файлов на основной компьютер с выбором, оставлять или удалять исходник на Raspberry Pi.

В `Настройки → Камера` можно включить автоматическое подключение к сохранённому Wi-Fi-профилю Raspberry Pi. Профиль сначала один раз создаётся штатными средствами Windows; приложение хранит только его имя, подключается через `netsh`, ожидает HTTP-сервис камеры и при закрытии окна может вернуть сеть, которая была активна до съёмки.

Свободная камера сохраняет скачанные файлы внутри выбранного каталога в подпапке даты съёмки `YYYY-MM-DD`, например `camera_downloads/2026-07-21`, поэтому материалы разных дней не смешиваются.

В режиме серии имя начинается с ID пикселя и содержит станцию, тип медиа и время. Каждый новый сценарий сохраняет все фото, видео и sidecar-файлы в отдельном каталоге `04_CAMERA/YYYY-MM-DD/<quarter>/<substrate>/<pixel>/N`, без повторного уровня `camera`. Старые каталоги `<pixel>/camera/N` не перемещаются и учитываются при продолжении нумерации. Для MP4 рядом создаются `_sync.json` и `_timeline.csv`: в таблице каждой секунде видео соответствует время измерения. Достижение токового лимита получает отдельную отметку возможного пробоя/шунта с временем измерения и MP4. Если включён переключатель `Создавать отдельное видео с показаниями стабильности`, после скачивания рядом появляется `*_telemetry.mp4`; исходный MP4 не изменяется.

Название из поля `Название снимка` используется и на Raspberry Pi, и после скачивания на основной компьютер. Если такое имя уже существует, приложение сохраняет следующий файл с суффиксом `_2`, не перезаписывая предыдущий снимок.

В блоке `Центральный кроп` задаётся доля кадра, которую нужно оставить по ширине и высоте. Например, `70 × 100%` симметрично убирает по 15% слева и справа. Справа показываются исходное разрешение/FPS и расчётное разрешение после кропа. Нижний терминал удалён; текущая операция отображается в компактной строке состояния.

Изображение LiveView автоматически увеличивается с сохранением пропорций, пока его ширина или высота не достигнет границы области просмотра. Список файлов Raspberry Pi расположен под LiveView слева, поэтому правая панель стала короче, а окно камеры занимает меньше высоты экрана.

При выключении или потере сети Raspberry Pi окно камеры остаётся открытым, останавливает локальный LiveView и позволяет подключиться повторно. Главное и камерное окна учитывают масштаб Windows; панель управления камерой прокручивается на экранах небольшой высоты.

Строка `Клиенты LiveView` в состоянии обычно показывает `1` при открытом потоке и `0` после остановки. Значение больше `1` означает, что к сервису подключён другой или оставшийся старый экземпляр приложения. При закрытии главного окна текущий клиент и поток камеры теперь завершаются автоматически.

Строка `Viewfinder Canon` показывает результат аппаратной проверки после остановки. Значение `выключен (проверено)` означает, что сервис не только завершил поток, но и установил обнаруженный параметр gPhoto2 `viewfinder`/`eosviewfinder` в `0`, после чего прочитал его обратно. Отсутствие слышимого щелчка не считается ошибкой само по себе: механическое поведение зависит от модели и режима Canon.

Блок `Экспозиция полноразмерного фото` появляется после инициализации камеры. Для каждого поддержанного параметра интерфейс показывает только варианты, которые камера вернула через gPhoto2 и разрешила изменять. После смены режима на диске Canon нажмите `Переинициализировать камеру`; для ручного управления ISO, выдержкой и диафрагмой рекомендуется режим `M`. Перед снимком сервис применяет каждое выбранное значение и читает его обратно для проверки; при несовпадении повторяет установку по точному индексу `Choice`. Если камера всё равно сохраняет другое значение, окно показывает название параметра, запрошенное и фактическое значения.

После выбора станции и пикселя кнопка `Параметры и запуск` открывает настройки ВАЯХ или стабильности с фиксированным пикселем. В камерном режиме повторный выбор пикселя и режим ВАЯХ `Вся серия последовательно` скрыты. После подтверждения параметров приложение автоматически делает фото `до`, показывает окно `Далее`/`Отмена`, запускает видео вместе с измерением, останавливает и скачивает видео, при выбранном объединении создаёт телеметрическую копию, снова показывает окно подтверждения и по кнопке `Далее` делает контрольное фото `после`. При токовом лимите стабильности питание безопасно выключается сразу, но видео продолжается ещё 5 секунд. Сервис Raspberry Pi, пример `systemd` для пользователя `user` и инструкция установки находятся в `raspberry_camera_service/`.

## Стабильность

В окне стабильности выбирается режим `Удерживать силу тока` или `Удерживать напряжение`. Во время прогона можно ввести новую цель или изменить её кнопками `±0.1`, `±0.25`, `±0.5`, `±1`. В режиме напряжения новое значение сразу передаётся на SMU без пропорциональной поправки; в режиме тока сохраняется программная обратная связь.

Если запись в COM-порт обрывается, измерение прекращается и приложение сначала пытается выключить выходы через текущее соединение, затем закрывает его и до четырёх раз повторно открывает SMU для установки 0 В и отключения обоих каналов. Если прибор не принял команды, окно явно требует ручного отключения выхода.

## Спектры

Во время автоподбора `T_int` live-окно показывает каждую пробу, её время интегрирования и статус, а приложение проверяет ток до и после каждой пробы. Обычный предел тока спектральной съёмки штатно завершает диапазон и не присваивает живому пикселю `CURRENT_LIMIT`; аварийный статус появляется только при достижении настройки `Ток пробоя/сгорания, мА`. Отсутствие контакта определяется по тому же порогу, что и в ВАЯХ: частичные данные автоматически удаляются, открывается окно перестановки/проверки контакта, и тот же пиксель снимается повторно. При токе пробоя можно удалить данные либо оставить CSV и диагностический XLSX. Оставленный XLSX записывается в журнал как снятый спектр и доступен для отчёта или калибровки, но приложение всё равно предлагает выбрать замену из той же четверти. Поле стартового напряжения запоминает последнее введённое значение независимо от напряжения открытия. При съёмке всей подложки выбираются сама подложка и произвольный стартовый пиксель; последовательность продолжается от него без возврата к более ранним пикселям. Переключатель `Только отмеченные пиксели этой подложки` ограничивает последовательность очередью выбранной подложки. Кнопка остановки завершает текущее считывание, сохраняет уже полученные данные и переводит SMU на 0 В.

Флажок ожидаемого спектра находится в столбце `Спектры` таблицы последних дат и метрик и показывается только до сохранённого спектра. Для выбранной строки кнопки над таблицей отмечают всю подложку или снимают с неё отметки; уже измеренные пиксели не меняются. Режим `Очередь серии` содержит только отмеченные пиксели, позволяет выбрать стартовый пункт, проходит остаток списка последовательно и завершается после последнего отмеченного пикселя.

Кнопка `Пересчитать спектр в отдельный файл` запускает расчёт только по запросу. Для каждой точки обработанный спектр нормируется на максимум, умножается на `CIE V(λ) / BPW34(λ)` и интегрируется. В окне выбора четвертей задаются допустимое процентное отклонение интеграла от медианы и доля измерений вне этого диапазона, при достижении которой проверяется переход к линейной модели. Если порог не достигнут, выбросы отбрасываются и используется медиана оставшихся значений. При достаточной доле отклонений и систематическом росте или падении сохраняется модель `integral(V) = a × V + b` и её `R²`. Линейная модель строится по точкам не ниже напряжения открытия и применяется к каждому пикселю только при `V ≥ Opening voltage`; ниже порога используется его прежний R/G/B-коэффициент. Если напряжение открытия отсутствует, границей становится минимальное напряжение калибровочного спектра. При следующем пересчёте приложение предлагает применить сохранённую модель четверти или заменить её калибровкой по выбранному пикселю. Исходная книга спектра не изменяется: результат сохраняется рядом в `SPECTRAL_RECALC_<pixel>_<time>.xlsx`.

## Коэффициенты И Пересчёт Серии

В настройках доступны геометрический и интегральный коэффициенты. До спектральной калибровки светимость считается по прежней формуле `Iфд × R/G/B × геометрический коэффициент`. После калибровки четверти произведение `спектральный интеграл четверти × интегральный коэффициент` заменяет коэффициент R/G/B:

`L = Iфд × integral(V) × интегральный коэффициент × геометрический коэффициент`.

Кнопка `Пересчитать мкА → кд/м²` повторно рассчитывает светимость во всех XLSX открытой серии. Для откалиброванных четвертей она использует спектральный интеграл и интегральный коэффициент вместо R/G/B; для остальных — прежний цветовой коэффициент. Если raw CSV отсутствует, он сначала восстанавливается из имеющегося XLSX. После успешной атомарной записи обновлённый XLSX заменяет прежний. Сам CIE/BPW34-пересчёт эта операция не запускает.

После ВАЯХ компактная миниатюра без числовых подписей сохраняется как `<серия>/thumbnails/<пиксель>_thumbnail.png`; в одной папке находятся превью всех пикселей серии. Новое измерение атомарно заменяет прежний файл. Обе кривые строятся линейно на общей шкале, как в итоговом XLSX; цвета повторяют live-график: ток OLED синий, фототок красный. Контрольный нерабочий цикл после пробоя не накладывается поверх полезной кривой. Кнопка `Обновить` и наведение проверяют наличие, версию и дату миниатюры относительно последней книги ВАЯХ и при необходимости пересоздают её.

В `Настройки → ВАЯХ доп.` отдельно задаются порог открытия по фототоку и количество следующих подтверждающих точек. Точкой открытия становится первое пересечение порога, после которого все указанные точки подряд также остаются не ниже порога; одиночный выброс игнорируется. Подтверждённое напряжение записывается автоматически, а ручной ввод предлагается только если устойчивый участок не найден.

Статус `BURNED` после превышения порога тока считается предварительным до контрольного цикла. Если пиксель снова показывает свет, сохраняется рабочий итоговый статус; `BURNED` остаётся только после подтверждённой потери работоспособности.

## Отчёты

В окне `Составить отчёт` доступны три варианта: полный отчёт, только ВАЯХ и только спектры. Для частичного отчёта отключённая часть не требуется в каталоге измерений и не создаётся в Origin-проекте или отладочной Excel-книге.

В Origin описание четверти включается в название серии: `ETM1 10nm (CLR1)`. В начале блока каждой кривой IV и J-L хранится заметка с полным идентификатором пикселя, а единица светимости записывается как `cd/m\+(2)`.

Флажки `Исключить четверти из отчёта` позволяют не включать четверти `1–4` во все выбранные разделы. CLI поддерживает повторяемый аргумент `--exclude-quarter N`.

Raw CSV и итоговый XLSX отдельно сохраняют выбранный режим, целевую уставку и фактически поданное напряжение. Окно управления показывает текущее время, напряжение, ток, фототок и яркость и позволяет безопасно остановить измерение.

## Что Должно Попасть В Репозиторий

В GitHub-репозитории `OLED_meas` должны храниться исходники, конфиги-примеры и документация. Папка с результатами измерений не коммитится:

- `OLED_series/` исключена через `.gitignore`;
- виртуальные окружения `env/` и `.venv/` исключены;
- локальные настройки `oled_app_settings.json` исключены, потому что там могут быть пути конкретного компьютера.

## Основные Файлы

- `oled_measurement_app_v2_5.py` - оригинальное рабочее приложение, оставлено как референс.
- `oled_modular_app.py` - новый основной вход модульного приложения.
- `oled_app/` - новый пакет модульного приложения: константы, настройки, утилиты, серии, hardware-слой, отчеты, измерения и GUI без правки референса.
- `oled_v2_app.py`, `oled_v2/` - отдельные launcher, backend, Stage 2 PoC и защита desktop-сеанса технического прототипа v2.
- `v2_frontend/` - исходники React/Vite, live-график Apache ECharts и `src/design-system/` с токенами, компонентами и эталоном серии; готовые assets входят в `oled_v2/static/`.
- `requirements-v2.txt` - дополнительные зависимости v2 и сборщика.
- `scripts/build_v2_frontend.ps1`, `scripts/build_v2_alpha.ps1` - production frontend и PyInstaller `onedir`.
- `packaging/oled_v2_alpha.spec` - спецификация тестового desktop-дистрибутива.
- `oled_app/camera/client.py` - HTTP-клиент сервиса камеры Raspberry Pi.
- `oled_app/camera/wifi.py` - переключение сохранённых Wi-Fi-профилей Windows для камеры.
- `oled_app/camera/telemetry_video.py` - создание локальной копии видео стабильности с отдельной верхней полосой U/I.
- `oled_app/gui/camera_window.py` - независимое тестовое окно LiveView, фото и видео.

## Нумерация Версий

Стабильный формат: `vMAJOR.MIDDLE.MINOR`. Для экспериментальной сборки допускается суффикс prerelease, например `v1.8.0-beta`.

- `MAJOR` - крупное изменение логики или структуры проекта.
- `MIDDLE` - функциональное обновление среднего масштаба.
- `MINOR` - небольшая правка или точечное добавление.

Текущая версия: `v2.0.0-alpha` — единый prerelease перехода на новый интерфейс.
Стабильная функциональная база: `v1.9.1`; основной Tkinter-вход сохранён.
