# План Предрелизного Разбиения Приложения На Модули

Документ фиксирует план постепенного переноса монолитного
логики `oled_measurement_app_v2_5.py` в отдельные модули. Перенос считается
предрелизной технической работой: основное приложение должно оставаться рабочим
на каждом шаге, а старый файл запуска сохраняется как референс.
Каркас новой структуры создается в новых файлах и пакете `oled_app/`, а
исходный `oled_measurement_app_v2_5.py` остается опорным источником текущего
поведения до тех пор, пока соответствующая часть не перенесена и не проверена.

## Цель

- Уменьшить риск случайно сломать измерения при правках GUI, отчетов или
  оборудования.
- Разделить GUI, журнал серии, измерительные workflow, hardware-слой,
  симулятор, настройки и отчеты.
- Упростить проверки отдельных частей без запуска всего интерфейса и без
  реального оборудования.
- Сохранить совместимый запуск через `oled_measurement_app_v2_5.py` как
  референсное приложение.
- Развивать новый основной каркас через `oled_modular_app.py` и пакет
  `oled_app/`.
- Использовать текущий монолит как эталон поведения: при сомнениях новая
  модульная реализация должна повторять исходный файл, а не заменять логику
  догадками.

## Целевая Структура

```text
oled_app/
  __init__.py
  main.py
  constants.py
  settings.py
  utils.py

  gui/
    __init__.py
    app.py
    start_screen.py
    measurement_menu.py
    settings_window.py
    ivl_window.py
    spectrum_window.py
    stability_window.py
    report_window.py
    widgets.py

  series/
    __init__.py
    manager.py
    journal.py
    paths.py
    statuses.py
    layout.py

  hardware/
    __init__.py
    probe.py
    ossila.py
    spectrometer.py
    auto_com.py
    simulator.py

  measurements/
    __init__.py
    ivl.py
    spectrum.py
    stability.py
    progress.py
    processing.py

  reports/
    __init__.py
    origin_report.py
```

Новый модульный каркас запускается отдельно:

```python
from oled_app.main import main

if __name__ == "__main__":
    main()
```

Корневой совместимый запуск нового каркаса:

```powershell
.\env\Scripts\python.exe .\oled_modular_app.py
```

Старый файл `oled_measurement_app_v2_5.py` не переписывается в thin-entrypoint:
он остается референсом для сравнения поведения.

## Правила Миграции

- Не переносить и переписывать поведение одновременно.
- Не изменять `oled_measurement_app_v2_5.py` во время модульного переноса без
  отдельного прямого запроса: это референсная реализация.
- Каркас и новые модули создаются отдельными файлами; исходный монолит
  используется как опорная реализация до завершения каждого переноса.
- Каждый шаг должен оставлять приложение запускаемым.
- GUI не должен напрямую работать с `xtralien`, `seabreeze` или Origin API.
- Измерительные модули не должны импортировать `tkinter`.
- Отчеты должны оставаться доступными из CLI-скрипта и из GUI.
- Локальные данные измерений, `report/`, `OLED_series/`, окружения и tools не
  добавляются в git.

Дальнейшие изменения должны обновлять этот список в том же коммите, где
переносится очередной слой.

### 1. Подготовить Каркас

Создать пакет `oled_app/`, пустые подпакеты и отдельный запуск
`oled_modular_app.py`. На этом этапе почти не переносить логику, только
зафиксировать структуру и проверить, что старый запуск не изменился.

Каркас не должен замещать `oled_measurement_app_v2_5.py`: новые файлы сначала
служат местом будущего переноса, а исходный файл остается рабочей опорой и
сравнительным эталоном.

Статус: выполнено в `v1.7.2`.

### 2. Подготовить Общие Константы, Настройки И Утилиты

Скопировать/подготовить в `constants.py`, `settings.py`, `utils.py` для нового
каркаса:

- `APP_VERSION`;
- имена файлов и папок измерений;
- `DEFAULT_APP_SETTINGS`;
- загрузку и сохранение настроек;
- даты, безопасные имена файлов, парсинг чисел;
- небольшие Excel helpers.

Это самый безопасный слой, потому что он почти не зависит от GUI и измерений.

Статус: выполнено в `v1.7.2`.

### 3. Подготовить `series/`

Скопировать/подготовить для нового каркаса:

- `PixelInfo`;
- `SeriesManager`;
- `SeriesJournal`;
- генерацию пикселей;
- создание папок измерений;
- статусы и цвета пикселей;
- геометрию карты подложкодержателя.

После шага новый модульный GUI должен использовать
`series.manager.SeriesManager`, а референсный файл остается без изменений.

Статус: выполнено в `v1.7.3`.

### 4. Подготовить `hardware/`

Скопировать/подготовить для нового каркаса:

- проверку оборудования;
- авто-COM Ossila;
- работу с `xtralien`;
- работу со спектрометром;
- установку и снятие встроенного симулятора.

Цель слоя: единая точка для real/simulator режима и кратких статусов
оборудования.

Статус: выполнено в `v1.7.4`.

### 5. Подготовить `reports/`

Скопировать/подготовить основную логику из `scripts/build_report_origin_workbook.py` в
`oled_app/reports/origin_report.py`.

CLI-скрипт оставить тонкой оболочкой:

```python
from oled_app.reports.origin_report import main

if __name__ == "__main__":
    raise SystemExit(main())
```

На первом шаге GUI может продолжать запускать CLI через `subprocess`; прямой
Python API можно подключить позже.

Статус: выполнено в `v1.7.5`.

### 6. Вынести `measurements/`

Переносить по одному workflow:

- ВАЯХ: параметры, измерение, Excel-книга, классификация статуса.
- Спектры: параметры, `SpectrumHelper`, подбор `T_int`, обработка, пики.
- Стабильность: параметры, цикл удержания тока, Excel-книга.

Это самый рискованный этап, поэтому каждый workflow переносится отдельно и
проверяется до следующего.

### 7. Вынести `gui/`

Когда бизнес-логика уже вынесена, разделить интерфейс:

- основной класс приложения;
- стартовый экран;
- меню серии;
- окно настроек;
- окно ВАЯХ;
- окно спектров;
- окно стабильности;
- окно отчета;
- progress windows и общие виджеты.

GUI должен только собирать параметры, запускать workflow и показывать результат.

### 8. Завершить Новый Вход

После успешного переноса сделать `oled_modular_app.py` полноценным основным
входом. README может предлагать новый запуск через пакет, но старая команда
`oled_measurement_app_v2_5.py` должна продолжать открывать референсное
приложение.

## Проверки После Каждого Шага

Минимальная проверка:

```powershell
.\env\Scripts\python.exe -m py_compile oled_measurement_app_v2_5.py scripts\build_report_origin_workbook.py
```

После появления пакета:

```powershell
.\env\Scripts\python.exe -m compileall oled_app scripts
```

Для отчетов:

```powershell
.\env\Scripts\python.exe .\scripts\build_report_origin_workbook.py --format xlsx --no-charts ...
```

Для GUI вручную:

- открыть приложение;
- открыть существующую серию;
- проверить карту статусов;
- открыть окна ВАЯХ, спектров, стабильности и отчета;
- проверить sim-режим;
- проверить real-режим и статус оборудования, если оборудование подключено.

## Критерий Готовности

Миграция считается завершенной, когда новый вход `oled_modular_app.py` работает
через независимые модули `measurements`, `hardware`, `series`, `reports` и
`gui`, а `oled_measurement_app_v2_5.py` остается неизменным референсом
поведения.
