# Подготовка данных отчета для Origin

Документ описывает промежуточную логику подготовки отчета по данным из папки
`report/measurements`. Текущий этап не меняет приложение: скрипт вынесен отдельно,
чтобы проверить правила отбора данных и затем встроить их в интерфейс.

## Назначение

Скрипт должен собрать один Origin-проект `.opju` без промежуточного выходного
`.xlsx`. Исходные файлы измерений остаются Excel-книгами приложения, но отчетный
файл создается напрямую через OriginPro Python API. Отладочный `.xlsx`-выход
оставлен только как fallback для проверки структуры данных без Origin.

## Входные данные

Ожидается структура:

```text
report/
  measurements/
    01_IVL_VAH/<date>/<series>/<subseries>/<pixel>/IVL_<pixel>_<timestamp>.xlsx
    02_SPECTRA/<date>/<series>/<subseries>/<pixel>/SPECTRUM_<pixel>_<timestamp>.xlsx
```

Для IVL/ВАЯХ используются листы `Cycle_N`. Для спектров используется лист
`Processed counts per s`, потому что он нормирует интенсивность на время
интегрирования и лучше подходит для сравнения разных напряжений.

## Быстрый прототип

Скрипт находится в `scripts/build_report_origin_workbook.py` и встроен в
GUI через кнопку серии `Составить отчет`. Его основной режим - `--format origin`: данные и графики сразу записываются
в `.opju`. Для этого на машине должен быть доступен пакет `originpro` из
OriginPro Python.

Базовый запуск:

```powershell
.\env\Scripts\python.exe .\scripts\build_report_origin_workbook.py `
  --measurements-dir .\report\measurements `
  --output .\report\origin_report.opju `
  --voltage-start 3 `
  --voltage-stop 5
```

Отладочная проверка без Origin и без создания Excel-графиков:

```powershell
.\env\Scripts\python.exe .\scripts\build_report_origin_workbook.py `
  --format xlsx `
  --measurements-dir .\report\measurements `
  --output .\report\origin_report_debug.xlsx `
  --voltage-start 3 `
  --voltage-stop 5 `
  --no-charts
```

Строгий режим для будущей интеграции в приложение:

```powershell
.\env\Scripts\python.exe .\scripts\build_report_origin_workbook.py `
  --measurements-dir .\report\measurements `
  --output .\report\origin_report.opju `
  --require-spectrum-pixel-selection `
  --spectrum-pixel CLR2_1=CLR2_1_1 `
  --spectrum-pixel CLR3_1=CLR3_1_2 `
  --voltage-start 3 `
  --voltage-stop 5 `
  --strict
```

В строгом режиме любое предупреждение считается ошибкой. Это нужно для GUI:
приложение должно сначала показать пользователю список подсерий и доступных
пикселей, затем передать выбранные пары `подсерия=пиксель` в скрипт.

## Целевая структура Origin-проекта

По открытому примеру `2026-06-25-report.opju` целевой файл должен собираться
сразу как Origin project, без промежуточного отчетного `.xlsx`.

Основные папки проекта:

```text
/IVL
  Book1
  /IV
    AllIV
    focus-графики по сериям
  /JL
    AlljL
    focus-графики по сериям
/Spectra
  <pixel_without_underscores>
  All
  <pixel_without_underscores>spctr
  Allspctr
  Allrelspctr
```

`README` и `Warnings` являются служебными workbook-страницами прототипа. Они не
участвуют в графиках и могут быть скрыты или исключены при финальном внедрении,
если отчет должен полностью повторять ручной шаблон.

## Правила отбора IVL/ВАЯХ

1. Для каждого пикселя выбирается последний файл `IVL_*.xlsx` по timestamp в имени.
2. Внутри файла выбирается последний лист `Cycle_N`.
3. В отчет попадают только пиксели, у которых последний цикл имеет статус
   `WORKING`.
4. Данные группируются по серии, подсерии и пикселю.
5. В Origin-книге `Book1` создается `Sheet1`. Для каждой серии записывается
   отдельная группа из трех колонок: `V`, `j`, `I\-(lum)`. В комментарии
   колонок `j` и `I\-(lum)` указывается серия.
6. Внутри группы данные всех рабочих пикселей серии идут вертикально: ВАЯХ
   одного пикселя, затем три пустые строки, затем ВАЯХ следующего пикселя.
7. В `Book1` создается `Sheet2`. Для каждой серии записывается пара колонок:
   `j`, `I\-(lum)`. Структура вертикальных блоков и три пустые строки между
   пикселями сохраняются.
8. Текущий прототип использует плотность тока `j` и светимость `I\-(lum)`,
   потому что именно эти величины построены в примерном файле. При внедрении
   можно добавить переключатель "ток/плотность" и "фотодиод/светимость", если
   отчет должен строиться по альтернативным колонкам.

Для графиков ВАХ строятся:

- `AllIV` в папке `/IVL/IV`: `V` по X, `j` по Y, все линии толщиной 2 pt;
- `AlljL` в папке `/IVL/JL`: `j` по X, `I\-(lum)` по Y, все линии толщиной 2 pt;
- focus-графики в `/IVL/IV` и `/IVL/JL` для каждой серии. Выбранная серия имеет
  толщину 3 pt и прозрачность 0%, остальные серии имеют толщину 2 pt и
  прозрачность 80%.
- Общие графики создаются как grouped/dependent plots. Focus-графики создаются
  как independent plots, чтобы толщина и прозрачность каждой линии задавались
  отдельно.
- Цвета линий берутся из установленной палитры Origin `Color4Line`.
- В `Comments` каждой колонки записывается имя ветки данных, например `CR1` или
  `CLR2`; пользовательские строки `CR1`, `CLR2`, `CLR3` не создаются.
- `Book1/Sheet2` не является независимой копией данных: колонки `j` и
  `I\-(lum)` задаются формулами `F(x)` со ссылками на соответствующие колонки
  `Book1/Sheet1`.

## Правила отбора спектров

1. Для каждой подсерии выбирается один пиксель.
2. Выбор пикселя должен задаваться приложением перед запуском подготовки отчета.
   В прототипе это передается аргументом:

   ```powershell
   python scripts/build_report_origin_workbook.py --spectrum-pixel CR1_2=CR1_2_2
   ```

3. Если явный выбор не задан, скрипт берет последний спектральный файл в
   подсерии. Если в подсерии есть несколько пикселей, это записывается в лист
   `Warnings`.
   Для будущего GUI предпочтителен режим `--require-spectrum-pixel-selection`:
   тогда подсерии без явного выбора не обрабатываются, а при `--strict` скрипт
   завершается с ошибкой.
4. Все выбранные пиксели должны иметь одинаковый диапазон и шаг напряжения.
   При заданных `--voltage-start`, `--voltage-stop`, `--voltage-step` скрипт
   фильтрует спектры до этой сетки; отсутствующие напряжения считаются
   предупреждением, а с `--strict` - ошибкой.
5. Для индивидуальных сеток приложение передает аргументы
   `--spectrum-voltage-grid PIXEL=START:STOP:STEP`. Общие спектральные графики
   строятся при максимальном напряжении, которое осталось у всех выбранных
   пикселей после фильтрации.

Для спектров формируются Origin-книги:

- отдельная книга на каждый выбранный пиксель, имя без подчеркиваний, например
  `CR122` для `CR1_2_2`. `Sheet1` содержит `\g(l)` в первой колонке и `I` для
  каждого напряжения в следующих колонках. Комментарий колонки: `<pixel> <V>V`;
- книга `All`, `Sheet1`: спектры всех выбранных пикселей при максимальном общем
  напряжении;
- книга `All`, `Sheet2`: те же спектры, нормированные каждый на свой максимум.

Для спектров строятся графики:

- `<pixel_without_underscores>spctr`: спектры одного пикселя при всех снятых
  напряжениях;
- `Allspctr`: спектры всех выбранных пикселей при максимальном общем напряжении;
- `Allrelspctr`: нормированные спектры при этом же напряжении.

Все спектральные графики используют линии толщиной 2 pt.
Спектральные графики также создаются grouped/dependent и используют ту же
палитру `Color4Line`. Комментарии колонок содержат имя пикселя и напряжение,
например `CR1_2_2 5V`.

## Графики в Origin

В `--format origin` скрипт создает worksheet- и graph-страницы напрямую через
OriginPro Python API:

- `Book1/Sheet1` и `Book1/Sheet2` для IVL/J-L данных;
- отдельные spectrum-книги и книгу `All`;
- `AllIV`, `AlljL`, focus-графики по сериям, спектральные графики и общие
  спектральные графики.

Для общих IVL и J-L графиков все линии имеют толщину 2 pt. Для focus-графиков
выбранная серия имеет толщину 3 pt и прозрачность 0%, остальные серии имеют
толщину 2 pt и прозрачность 80%. В `--format xlsx` эти требования также
дублируются на листе `Origin_plot_specs`, но этот режим нужен только для
диагностики.

## Контракт для будущей интеграции в приложение

Приложение должно подготовить для скрипта:

- путь к папке `measurements`;
- путь к выходному `.opju`;
- дату ВАЯХ (`--ivl-date`) и дату спектров (`--spectrum-date`), если отчет должен собираться не по последним файлам;
- список выбранных пикселей для спектров в формате `подсерия -> пиксель`;
- ожидаемые `voltage_start`, `voltage_stop`, `voltage_step`;
- режим strict/soft для проверки сетки напряжений;
- доступность OriginPro Python API `originpro` на машине, где выполняется
  прямой `.opju`-вывод.

Скрипт возвращает:

- выходной `.opju`;
- предупреждения на worksheet `Warnings`;
- ненулевой код выхода только при критической ошибке или при `--strict`, если
  нарушены обязательные условия.

## Ограничения прототипа

- Прямой `.opju`-вывод требует установленный Origin/OriginPro Python API
  `originpro`; без него скрипт завершится с понятной ошибкой и не будет создавать
  промежуточный `.xlsx`.
- В текущем окружении проверен OriginPro 2024 через пакет `originpro`: тестовый
  файл `report/origin_report_generated_v7.opju` сохранен и затем открыт через
  API для проверки структуры и стилей линий.
- Если OneDrive или Excel блокирует исходный файл, скрипт пропускает его и пишет
  предупреждение.
- В тестовом запуске с `--voltage-start 3 --voltage-stop 5` есть предупреждение
  по спектру `CR1_2_2`: его сетка начинается с 2.6 В, а не с 3.0 В. Это
  содержательная проверка данных, а не ошибка генерации Origin-файла.
- Режим `--keep-origin-open` пригоден только для ручной отладки. Для интеграции
  в приложение нужно запускать скрипт без него: так процесс возвращает код `0`
  после успешного сохранения и закрывает управляемый экземпляр Origin.
