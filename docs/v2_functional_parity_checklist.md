# Чек-лист Функционального Соответствия v1.9.1 → v2.0

Дата фиксации: 2026-07-30

Эталонный commit: `e85a7a6` (`v1.9.1`)

Рабочий prerelease перехода: `v2.0.0-alpha`

## 1. Назначение

Этот документ фиксирует поведение модульного Tkinter-приложения, которое новая
оболочка v2 обязана сохранить. Он является результатом этапа 0 плана
`docs/v2_interface_plan.md` и используется как приёмочный чек-лист для API,
frontend, упаковки и параллельной проверки.

До закрытия всех обязательных пунктов:

- `oled_modular_app.py` остаётся штатным входом и запускает Tkinter;
- `oled_measurement_app_v2_5.py` остаётся нетронутым референсом;
- v2 разрабатывается через отдельные entrypoint и пакеты;
- форматы серий, журнала, raw CSV и итоговых XLSX не меняются;
- frontend не получает прямого доступа к SMU, спектрометру или файлам измерений;
- аппаратная проверка и безопасная установка `0 В` остаются обязанностью Python.

Обозначения состояния v2:

- `[ ]` — ещё не перенесено;
- `[~]` — реализовано, но не прошло полный сценарий проверки;
- `[x]` — реализовано и проверено относительно эталона.

## 4. Переходы И Доступность

| Из состояния | Действие | Результат / ограничение |
|---|---|---|
| Старт | Открыть или создать серию | Инициализация `SeriesManager` и переход на панель серии |
| Панель серии | Спектры или стабильность | Доступны только после подходящей ВАЯХ; для спектра обязательно напряжение открытия |
| Таблица/карта | Выбрать пиксель | Один и тот же Pixel ID выделяется и используется быстрыми действиями |
| ВАЯХ серии | Выбрать стартовый пиксель | Более ранние элементы физического порядка пропускаются |
| Спектр подложки | Выбрать стартовый пиксель | Последовательность не зацикливается и не возвращается к более ранним пикселям |
| Очередь спектров | Запустить со стартового пикселя | Только явно отмеченные и ещё не снятые пиксели; завершение после последнего |
| Измерение | Остановить | Контроллер получает stop, SMU переводится в безопасное состояние, частичные данные обрабатываются по правилам workflow |
| Камера серии | Запустить измерение | Камерное окно остаётся координатором сценария, а измерение выполняется существующим Python workflow |
| Любой пересчёт | Завершить | Исходные спектральные книги не меняются; общий пересчёт светимости заменяет только предусмотренные итоговые книги |

## 5. Ошибки И Решения Оператора

| Событие | Обязательное решение |
|---|---|
| Невалидное поле формы | Ошибка рядом с полем или блокирующее сообщение; измерение не запускается |
| Рабочая ВАЯХ без устойчивого opening voltage | Ручной ввод напряжения или отмена ввода без подмены автоматического результата |
| `NO_CONTACT` при ВАЯХ серии | Повтор того же пикселя; пропуск остатка этой подложки; либо продолжение обычной очереди |
| Предварительный высокий ток ВАЯХ | Дополнительный подтверждающий цикл; `BURNED` не становится окончательным без нерабочего подтверждения |
| `NO_CONTACT` при спектре | Частичные данные удаляются; повторяется тот же пиксель; замена пикселя не предлагается |
| `CURRENT_LIMIT` при спектре | Удалить частичные данные или сохранить диагностический CSV/XLSX; затем выбрать замену только из той же физической четверти |
| Потеря контакта/ошибка оборудования | Workflow завершается через безопасный shutdown; traceback остаётся в логе, оператор видит понятное сообщение |
| Нет точки ВАЯХ для уставки стабильности | Ручной ввод V, затем подтверждение старта на `0.9 × V` |
| Закрытие активного окна | Сначала безопасная остановка и попытка установить `0 В`; мгновенное закрытие не является штатным действием |
| Камера занята | Новая операция не запускается до завершения текущей |
| Камера недоступна через текущую сеть | При включённой опции подключение к сохранённому Wi-Fi-профилю, ожидание сервиса и возврат прежней сети при ошибке/закрытии |

## 6. Контракты Данных

### 6.1. Серия И Журнал

- `series_config.json` открывается без миграции и сохраняет четыре четверти.
- `series_journal.xlsx` содержит листы `Series`, `Quarters`, `Pixels`,
  `Measurements`.
- Заголовки `PIXEL_HEADERS` и `MEASUREMENT_HEADERS` из
  `oled_app/constants.py` являются совместимым контрактом.
- Измерения остаются под `measurements/<тип>/<дата>/<четверть>/<подложка>/<пиксель>`.
- Калибровка остаётся под `calibration/<четверть>`, миниатюры — под
  `thumbnails`, raw CSV — под настроенной папкой `raw_data`.

### 6.2. Raw CSV

- ВАЯХ: `cycle`, `point`, `date_time`, `elapsed_s`, set/measured voltage,
  LED current в A/мА, photodiode voltage/current в A/мкА.
- Спектр summary: электрические величины, светимость, `integration_time_s`,
  status, raw/processed peak, FWHM, список пиков и baseline.
- Спектр data: `point`, `voltage_set_V`, `integration_time_s`,
  `wavelength_nm`, `raw_counts`, `dark_counts`.
- Стабильность: время, режим, target/revision, токовая и напряжённая уставки,
  applied voltage, измеренные электрические величины, плотность тока и светимость.
- Запись каждой точки немедленно flush-ится; v2 не буферизует raw-данные только
  во frontend.

### 6.3. XLSX

- ВАЯХ: `Summary` и `Cycle_N`; заголовки данных и расчётные единицы сохраняются.
- Спектр: `Сводка`, `Спектры`, `Processed counts per s`, `Raw spectra`,
  `Dark corrected`, `Baseline`, `Описание полей`.
- Стабильность: текущие target и applied values остаются раздельными столбцами.
- Формулы, диаграммы, даты, статус и относительные пути в журнале сравниваются
  после нормализации времени создания файла.

и наличие диаграмм; ZIP-байты XLSX не сравниваются из-за метаданных времени.

## 8. Текущая Автоматическая Защита

На момент фиксации `unittest discover` выполняет 154 автоматических теста. Они
покрывают:

- физический layout и lifecycle Tk;
- очередь, стартовые пиксели, `NO_CONTACT` и `CURRENT_LIMIT`;
- спектральный подбор `T_int` и проверки тока;
- raw → XLSX, калибровку и пакетный пересчёт;
- управление уставкой стабильности и аварийный shutdown;
- отчётные выборки;
- Raspberry Pi camera API, Wi-Fi и телеметрическое видео.

Перед переводом любого пункта матрицы в `[x]` требуется:

1. пройти соответствующий API-тест;
2. пройти frontend/e2e-сценарий;
3. сравнить нужный golden-сценарий;
4. подтвердить безопасную остановку для аппаратного workflow;
5. оставить эквивалентный сценарий работающим в Tkinter до решения о его снятии.
