# Исследование и реализация выбора качества фото и видео камеры

Дата: 2026-07-22

Статус: реализованы динамический выбор JPEG-качества, видеопараметров и экспозиции полноразмерного фото; требуется проверка на реальной камере.

## Вывод

Динамический выбор качества возможен, но `gphoto2 --summary` для этого недостаточно. Он подходит для общей информации и модели камеры. Реальные доступные параметры и их варианты надо запрашивать у подключённой камеры через `gphoto2 --list-config` / `--list-all-config`, затем читать нужный параметр через `gphoto2 --get-config <путь>`.

Названия и наличие параметров зависят от модели, версии прошивки и драйвера libgphoto2. Поэтому нельзя надёжно зашить один список разрешений для всех Canon.

## Фото

Для полноразмерной фотографии следует искать доступные виджеты качества/размера, в первую очередь параметры наподобие `imageformat` и `imagesize`, но выбирать их надо по фактическому выводу конкретной камеры. `--get-config` возвращает текущий вариант и список `Choice`, после чего выбранное значение можно применить через `--set-config-value` или безопаснее через `--set-config-index`.

Важно учитывать формат результата: текущий сервис заранее создаёт имя с расширением `.jpg`. Если камера будет переведена в RAW или RAW+JPEG, потребуется изменить обработку имён, нескольких скачанных файлов и типов файлов. Поэтому первый вариант интерфейса разумно ограничить только JPEG-размерами/качеством, если камера их предоставляет.

## Экспозиция полноразмерного фото

Для ISO, выдержки, диафрагмы и экспокоррекции применяется тот же динамический подход. Сервис ищет фактически опубликованные камерой виджеты `iso`, `shutterspeed`, `aperture`, `exposurecompensation` и совместимые варианты имён, затем оставляет только изменяемые параметры с несколькими вариантами `Choice`.

Список нельзя считать постоянным даже для одной модели: он зависит от положения диска режимов, прошивки и libgphoto2. Поэтому возможности кэшируются только после инициализации, а после смены режима пользователь должен запустить повторную инициализацию. Перед снимком каждое значение проверяется по кэшу, записывается через `--set-config-value` и читается обратно через `--get-config`.

## Видео

Текущее видео не записывается штатным видеорежимом Canon. Сервис получает preview/LiveView командой `gphoto2 --stdout --capture-movie` и кодирует эти JPEG-кадры через FFmpeg. Здесь есть два разных уровня качества:

1. Разрешение и FPS входного LiveView зависят от камеры и поддержки libgphoto2; они не обязательно переключаются и могут не соответствовать максимальному качеству внутренней записи камеры.
2. Сжатие итогового MP4 контролирует Raspberry Pi: это H.264, preset и один `ffmpeg_crf` из `config.json`. Пользовательский интерфейс не выдаёт параметры кодировщика за возможности камеры и не добавляет деталей сверх входного LiveView.

Если конкретная камера экспортирует параметры внутреннего movie quality через конфигурационные виджеты, их можно обнаружить тем же способом, но текущая архитектура не использует внутренний видеофайл камеры. Поддержка такого режима будет отдельной функцией, а не простой настройкой существующего FFmpeg-потока.

## Реализованная схема API

При проверке на Raspberry Pi полезно сохранить фактический вывод:

```bash
gphoto2 --summary
gphoto2 --list-config
gphoto2 --list-all-config
gphoto2 --get-config imageformat
gphoto2 --get-config imagesize
```

Короткие имена могут оказаться неоднозначными; для API лучше хранить полный путь конфигурационного виджета, полученный из `--list-config`.

Сервис отдаёт read-only `GET /api/camera/capabilities` со списками поддержанных JPEG-параметров фото, изменяемых параметров экспозиции, настроек качества/размера LiveView и настроек FPS. Выбранные JPEG-параметры и экспозиция передаются в `POST /api/photo/capture` внутри `photo_settings`. Видео-параметры передаются как `video_settings` в `POST /api/liveview/start` и `POST /api/video/start`. Любой путь и вариант проверяется по кэшу capabilities перед применением к камере.

В первом этапе реализовано:

- показать только обнаруженные камерой JPEG-варианты для фото;
- показать только изменяемые ISO, выдержку, диафрагму и экспокоррекцию, реально обнаруженные в текущем режиме камеры;
- проверять фактически установленное значение экспозиции чтением из камеры до запуска снимка;
- для видео отдельно показать выбор качества/размера и FPS, только если камера экспортирует соответствующие независимые виджеты;
- если камера не предоставляет управление FPS, отключить список и показывать только измеренную частоту входного потока;
- не обещать внутреннее 4K/Full HD качество Canon, пока сервис пишет preview-поток;
- capabilities кэшируются только на время подключения и обновляются после повторной инициализации камеры;
- произвольные пути и значения от клиента отклоняются, если их нет в ранее полученном списке;
- RAW и RAW+JPEG скрыты, чтобы сохранить гарантию одного JPEG-файла;
- `DELETE /api/files/{file_id}` удаляет только зарегистрированный файл внутри каталога сервиса;
- desktop вызывает удаление только после проверки размера, SHA-256 и атомарного завершения локального `.part`.

## Нужно проверить на реальном оборудовании

- точную модель Canon и версии `gphoto2` / `libgphoto2` на Raspberry Pi;
- полный вывод `--list-config` и `--list-all-config`;
- какие параметры доступны только после включения режима захвата;
- какие ISO, выдержка, диафрагма и экспокоррекция доступны у Canon EOS 5D Mark II в режиме `M`;
- меняется ли разрешение `--capture-movie` от настроек камеры;
- нагрузку CPU, пропуски кадров и размер файла при настроенных на Raspberry Pi CRF/preset;
- фактические названия и сочетания `liveviewsize`, `output`, movie/video quality и frame-rate виджетов конкретной модели;
- поведение фото для JPEG, RAW и RAW+JPEG.

Для использования новых возможностей Raspberry Pi нужно обновить файлы сервиса и перезапустить systemd-службу. До проверки на оборудовании набор доступных вариантов экспозиции считается зависящим от конкретной камеры.

## Источники

- [Справка gphoto2 CLI](https://gphoto.github.io/doc/manual/ref-gphoto2-cli.html): назначение `--summary`, `--list-config`, `--list-all-config`, `--get-config` и `--set-config-*`.
- [gPhoto2: remote controlling cameras](https://gphoto.sourceforge.io/doc/remote/): конфигурация удалённой съёмки, различия поддерживаемых параметров между моделями и зависящие от модели настройки LiveView.
- [libgphoto2 camera API](https://gphoto.github.io/doc/api/gphoto2-camera_8c.html): конфигурация камеры представлена динамическим деревом виджетов, получаемым от драйвера конкретной камеры.
