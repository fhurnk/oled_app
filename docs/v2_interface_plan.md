# План Интерфейса OLED Measurement App v2.0

Статус документа: выполнение начато в `v2.0.0-alpha`.
Целевая версия: `v2.0.0`.
Текущий прогресс: `docs/v2_migration_status.md`.
Чек-лист соответствия v1.9.1 → v2.0:
`docs/v2_functional_parity_checklist.md`.

Текущий Tkinter-интерфейс остаётся штатным приложением до завершения тестирования
и отдельного решения о переключении основного входа.

## 1. Цель v2.0

Версия 2.0 должна заменить визуально устаревший Tkinter-интерфейс современным
настольным интерфейсом, сохранив существующую измерительную логику и совместимость
с данными серий.

Основные требования:

- приложение запускается как Windows `.exe`;
- интерфейс открывается в собственном окне без отдельного браузера, вкладок и
  адресной строки;
- внутри приложения допускается локальный HTTP-сервис на `localhost`;
- пользователь не должен устанавливать Python, Node.js или запускать сервер
  вручную;
- сохраняются ВАЯХ, спектры, стабильность, камера, отчёты, пересчёты, журнал и
  эмулятор;
- форматы существующих серий, CSV и XLSX остаются совместимыми;
- управление оборудованием и правила безопасного отключения не переносятся во
  frontend.

## 2. Рекомендуемая Архитектура

### 2.1. Состав приложения

```text
OLED Measurement App.exe
        │
        ├── Desktop launcher
        │     ├── выбирает свободный локальный порт
        │     ├── запускает Python backend
        │     ├── ожидает готовность backend
        │     └── открывает собственное окно WebView2
        │
        ├── Python backend на 127.0.0.1
        │     ├── существующая логика измерений
        │     ├── работа с SMU и спектрометром
        │     ├── журнал серии, CSV и XLSX
        │     ├── камера Raspberry Pi
        │     ├── отчёты и пересчёты
        │     └── REST API + WebSocket
        │
        └── React frontend
              ├── страницы приложения
              ├── интерактивная карта держателя
              ├── таблицы и очереди
              ├── live-графики
              └── диалоги и уведомления
```

### 2.2. Технологический стек

| Слой | Рекомендуемая технология | Назначение |
|---|---|---|
| Frontend | React + TypeScript | Современный компонентный интерфейс |
| Сборка frontend | Vite | Сборка статических HTML/CSS/JS без Node.js на компьютере пользователя |
| Локальный backend | FastAPI | API поверх существующей Python-логики |
| Live-обновления | WebSocket | Точки измерений, прогресс, аппаратные состояния и запросы оператора |
| Окно приложения | pywebview + Microsoft Edge WebView2 | Собственное Windows-окно без браузерного интерфейса |
| Графики | Apache ECharts или Plotly.js | Масштабируемые интерактивные live-графики |
| Сборка `.exe` | PyInstaller или Nuitka | Упаковка Python backend, launcher и frontend |
| Установщик | Inno Setup или NSIS | Ярлык, иконка, удаление и обновление приложения |

React отвечает только за представление и пользовательские действия. Python
backend остаётся единственным слоем, имеющим доступ к оборудованию, файловой
системе измерений и журналу серии.

### 2.3. Почему Не Electron

Electron также позволяет создать собственное окно, но включает отдельные Chromium
и Node.js. Для текущего Python-проекта это увеличивает размер дистрибутива и
добавляет ещё один процессный слой.

Связка `pywebview + WebView2` использует системный WebView Windows и проще
связывается с существующим Python-кодом. Если в дальнейшем потребуется сложная
система автоматических обновлений или кроссплатформенная оболочка, отдельно можно
оценить Tauri с Python sidecar.

## 3. Запуск И Завершение

### 3.1. Запуск

1. Пользователь запускает `OLED Measurement App.exe`.
2. Launcher создаёт одноразовый токен сеанса.
3. Launcher выбирает свободный порт и запускает backend только на `127.0.0.1`.
4. Выполняется локальная проверка готовности.
5. Открывается окно WebView2 с интерфейсом приложения.
6. Frontend получает начальное состояние, настройки и статус оборудования.
7. После открытия интерфейса начинается фоновая проверка SMU, спектрометра и
   камеры.

Пользователь не видит порт, консоль, сервер или браузер.

### 3.2. Завершение

1. Frontend отправляет запрос на закрытие.
2. Если идёт измерение, показывается собственный диалог безопасной остановки.
3. Backend останавливает измерение и переводит SMU в безопасное состояние.
4. Завершаются LiveView, камера и фоновые задачи.
5. Backend подтверждает завершение.
6. Launcher закрывает WebView и локальный процесс.

При аварийном закрытии launcher должен отдельно вызвать аварийный shutdown SMU
перед принудительным завершением backend.

## 4. Безопасность Localhost

Локальный API управляет реальным лабораторным оборудованием, поэтому обычной
привязки к `localhost` недостаточно.

Обязательные ограничения:

- backend слушает только `127.0.0.1`, а не все сетевые интерфейсы;
- порт выбирается случайно при каждом запуске;
- launcher передаёт frontend одноразовый токен сеанса;
- каждый REST- и WebSocket-запрос проверяет токен;
- разрешается только ожидаемый `Origin`;
- API не принимает команды оборудования до завершения инициализации;
- одновременно допускается только один управляющий клиент;
- все команды запуска и остановки журналируются;
- backend автоматически завершается вместе с desktop-окном;
- в production отключаются Swagger/OpenAPI UI и отладочные endpoints;
- приложение не требует подключения к интернету.

Сервис Raspberry Pi камеры остаётся отдельным сетевым компонентом. Его адрес и
порт продолжают задаваться в настройках камеры.

## 5. Информационная Архитектура

### 5.1. Основное Окно

```text
┌──────────────────────────────────────────────────────────────────────┐
│ OLED Measurement App 2.0    Серия: CR...    ● SMU  ● SPEC  ● CAM  │
├───────────────┬──────────────────────────────────────────────────────┤
│ Обзор         │                                                      │
│ Серия         │              Текущая рабочая страница                │
│ ВАЯХ          │                                                      │
│ Спектры       │     карта / таблица / форма / live-график           │
│ Стабильность  │                                                      │
│ Камера        │                                                      │
│ Отчёты        │                                                      │
│───────────────│                                                      │
│ Настройки     │                                                      │
│ Диагностика   │                                                      │
├───────────────┴──────────────────────────────────────────────────────┤
│ Готово · выбран CR1_1_1 · последнее автосохранение 14:32           │
└──────────────────────────────────────────────────────────────────────┘
```

Постоянные элементы:

- левая навигационная панель;
- название и путь активной серии;
- индикатор `Реальное оборудование` или `Эмулятор`;
- отдельные статусы SMU, спектрометра и камеры;
- кнопка повторной проверки оборудования;
- нижняя строка текущей операции и автосохранения;
- постоянно видимая безопасная остановка во время измерения.

До открытия серии доступны стартовая страница, свободная камера, настройки и
диагностика. Измерительные разделы открываются после выбора серии.

### 5.2. Навигационная Логика

```text
Запуск
  → выбор или создание серии
    → рабочая панель серии
      → выбор пикселя
        → настройка измерения
          → проверка параметров и оборудования
            → активное измерение
              → обработка и сохранение
                → обновлённая рабочая панель серии
```

Спектры и стабильность остаются недоступными, пока в журнале нет подходящей ВАЯХ.
Причина недоступности показывается рядом с элементом, а не только через неактивную
кнопку.

## 6. Экраны

### 6.1. Стартовая Страница

Содержимое:

- последние открытые серии;
- поиск по дате, кодовому слову и пути;
- дата напыления, дата создания и количество измерений;
- действия `Открыть`, `Создать серию`, `Открыть папку`;
- компактный выбор корневой папки серий;
- состояние оборудования;
- вход в свободную камеру;
- понятное пустое состояние, если серии ещё не найдены.

Двойной щелчок по серии продолжает открывать её.

### 6.2. Создание И Редактирование Серии

Рекомендуется мастер из трёх шагов:

1. Папка, дата напыления и кодовое слово.
2. Базы, цвета и описания четырёх четвертей.
3. Предпросмотр имён подложек и пикселей, итоговая проверка.

Карта подложкодержателя обновляется сразу при вводе. Ошибки показываются рядом с
полями, не стирая уже введённые данные.

### 6.3. Рабочая Панель Серии

Верхние сводные карточки:

- количество пикселей;
- количество последних ВАЯХ;
- количество снятых спектров;
- количество измерений стабильности;
- размер очереди спектров;
- дата последней операции.

Основная область:

- интерактивная карта подложкодержателя;
- карточка выбранного пикселя;
- последние метрики и статусы;
- миниатюра ВАЯХ;
- история ВАЯХ по датам;
- таблица всех пикселей;
- быстрый запуск подходящего измерения.

Карта и таблица синхронизированы: выбор в одном компоненте выделяет тот же пиксель
в другом. Статус показывается цветом, значком и текстом.

### 6.4. Таблица Пикселей И Очередь Спектров

Таблица сохраняет текущие сведения:

- Pixel ID;
- статус;
- напряжение открытия;
- дата и метрики ВАЯХ;
- дата, пики и максимум спектра;
- дата стабильности.

Дополнительно:

- фиксированный заголовок;
- сортировка и фильтры;
- горизонтальная прокрутка без потери Pixel ID;
- компактный и расширенный режим строки;
- переход к файлу последнего измерения;
- массовый выбор подложки.

Очередь спектров:

- флажок находится в столбце спектров до сохранения спектра;
- показывается количество отмеченных пикселей;
- можно отметить или снять всю выбранную подложку;
- отдельная панель показывает фактическую последовательность;
- стартовый пиксель задаёт начало без изменения существующей логики порядка;
- уже снятые спектры не включаются в очередь.

### 6.5. ВАЯХ

Блоки формы:

- `Конкретный пиксель` или `Вся серия последовательно`;
- пиксель или стартовый пиксель;
- начало, конец и шаг sweep;
- время на точку;
- количество циклов и задержка;
- предел тока.

Перед запуском показываются:

- число точек и циклов;
- ориентировочная продолжительность;
- первый и последний пиксели последовательности;
- площадь пикселя и коэффициент светимости;
- выбранный предел тока;
- результат preflight-проверки SMU.

Расширенные параметры доступны в сворачиваемой секции с явной пометкой, что они
влияют на классификацию и безопасность.

### 6.6. Спектры

Верхний переключатель режима:

- `Один пиксель`;
- `Подложка`;
- `Очередь серии`.

Интерфейс показывает только поля выбранного режима:

- пиксель или стартовый пиксель;
- подложка;
- только отмеченные пиксели подложки;
- напряжение открытия;
- ручное или журнальное стартовое напряжение;
- конечное напряжение и шаг;
- предел тока;
- тип LED;
- список предстоящих пикселей.

Перед запуском пользователь видит итоговую последовательность и количество
ожидаемых спектральных точек.

### 6.7. Стабильность

Содержимое:

- пиксель;
- `Удерживать силу тока` или `Удерживать напряжение`;
- целевая уставка;
- предел напряжения;
- предел тока;
- длительность;
- интервал точки;
- интервал автосохранения;
- расчётное стартовое напряжение из ВАЯХ;
- предупреждение, если расчёт невозможен.

Поля, не относящиеся к текущему режиму, скрываются. Рядом с уставкой показывается,
что именно backend будет изменять во время обратной связи.

### 6.8. Единая Страница Активного Измерения

Общая компоновка:

- сверху — тип измерения, пиксель, этап и прошедшее время;
- слева — live-график;
- справа — текущие числовые значения и состояние оборудования;
- снизу — таблица точек или событий;
- в заметной зоне — безопасная остановка.

ВАЯХ:

- переключение `I / ФД` и `J / L`;
- напряжение, ток OLED, фототок, плотность тока и светимость;
- цикл и точка sweep.

Спектры:

- raw и corrected counts/s;
- текущее напряжение и `T_int`;
- состояние подбора `T_int`;
- насыщение, максимум и найденные пики;
- положение текущего пикселя в последовательности.

Стабильность:

- измеренные ток, напряжение, фототок и светимость;
- целевая и применённая уставка;
- кнопки изменения цели;
- время следующего автосохранения;
- отметки событий на временном графике.

### 6.9. Аварийные И Операторские Решения

Модальные диалоги используются только там, где без ответа оператора продолжать
нельзя.

`NO_CONTACT`:

- крупный заголовок `Нет контакта`;
- проверяемый пиксель;
- сообщение об удалении частичных данных;
- инструкции по перестановке;
- действия `Повторить тот же пиксель` и `Остановить`.

`CURRENT_LIMIT`:

- фактический ток и установленный аварийный порог;
- предупреждение о возможном пробое;
- выбор удалить данные или сохранить диагностический XLSX;
- после решения — выбор замены из той же физической четверти;
- опасное действие визуально отделено от обычного.

Закрытие активного измерения:

- объяснение, что сначала будет установлено `0 В`;
- действия `Безопасно остановить` и `Продолжить измерение`;
- отсутствие обычной кнопки мгновенного принудительного закрытия.

### 6.10. Камера

Одна страница поддерживает два режима:

- свободная камера;
- камера открытой серии.

Компоновка:

- большая область LiveView;
- поверх изображения — рамка центрального кропа;
- справа — состояние подключения и параметры;
- снизу — файлы Raspberry Pi и последние локальные загрузки.

Разделы правой панели:

- подключение к Raspberry Pi;
- станция и пиксель;
- качество фото и видео;
- ISO, выдержка, диафрагма и экспокоррекция;
- центральный кроп;
- snapshot, фото и видео;
- управляемый сценарий `фото до → измерение с видео → фото после`.

Недоступные параметры камеры не показываются. Состояния подключения, записи,
скачивания и создания телеметрического видео отображаются отдельными шагами.

### 6.11. Отчёты

Мастер отчёта:

1. Тип отчёта, даты измерений и исключаемые четверти.
2. Подложки, пиксели и диапазоны напряжения.
3. Путь сохранения и итоговая сводка.

Перед запуском показываются:

- выбранные даты;
- исключённые четверти;
- выбранные спектральные пиксели;
- общий или индивидуальные диапазоны;
- формат `.opju` или диагностический `.xlsx`;
- предупреждения о несовместимых диапазонах.

### 6.12. Настройки

Категории:

- Общие;
- Оборудование;
- Единицы и коэффициенты;
- ВАЯХ;
- Спектры;
- Стабильность;
- Камера;
- Эмулятор;
- Файлы и хранение;
- Диагностика.

Основные и расширенные настройки визуально разделяются. Для опасных порогов
показывается пояснение влияния. Несохранённые изменения отмечаются, а при закрытии
предлагается сохранить или отменить их.

### 6.13. Диагностика

Отдельная страница должна показывать:

- версию приложения и backend;
- режим оборудования;
- обнаруженный COM-порт;
- состояние SMU и спектрометра;
- адрес и состояние камеры;
- путь текущей серии и журнала;
- последние ошибки;
- кнопку копирования диагностической сводки;
- путь к локальным логам.

Секреты и одноразовые токены в диагностическую сводку не включаются.

## 7. Визуальная Система

### 7.1. Характер

Интерфейс должен выглядеть как современное профессиональное лабораторное ПО:
точное, спокойное и информационно плотное, но не перегруженное.

Не следует копировать стандартный Bootstrap, использовать чрезмерные градиенты,
неоновые эффекты или крупные декоративные блоки, уменьшающие рабочую область.

### 7.2. Базовые Токены

| Элемент | Рекомендация |
|---|---|
| Основной фон | холодный светло-серый |
| Рабочая поверхность | белый |
| Боковая панель | глубокий графитовый или тёмно-синий |
| Основной акцент | насыщенный синий |
| Скругление | 8–12 px |
| Базовый шаг отступов | 8 px |
| Основной шрифт | Segoe UI Variable или Inter |
| Высота строки таблицы | 36–40 px |
| Анимации | 150–200 мс, только для состояния и навигации |

### 7.3. Статусы

| Смысл | Цвет |
|---|---|
| Готово / рабочий | зелёный |
| Требуется внимание | оранжевый |
| Критическая ошибка / пробой | красный |
| Не измерен / недоступен | серый |
| Выбран / в очереди | синий |
| Измерение выполняется | фиолетовый |

Цвет всегда сопровождается подписью, значком или формой маркера.

### 7.4. Иерархия Действий

- одна основная кнопка на рабочую область;
- вторичные действия — нейтральные;
- опасные действия — красные и отделены пространственно;
- `Остановить и поставить 0 В` всегда заметнее остальных элементов;
- успешные фоновые действия показываются уведомлением, а не модальным окном;
- ошибки полей показываются рядом с полем;
- модальные окна используются только для блокирующих решений.

### 7.5. Темы И Масштабирование

Первой реализуется светлая тема. Тёмная тема добавляется после стабилизации
компонентов и графиков.

Обязательная проверка:

- Windows scaling 100%, 125%, 150%, 175% и 200%;
- рабочие разрешения от 1366×768;
- рекомендуемая область 1440×900 и выше;
- отсутствие горизонтальной прокрутки всей страницы;
- сохранение читаемости графиков и таблиц.

## 10. Упаковка

### 10.1. Рекомендуемый Дистрибутив

Для первого стабильного релиза рекомендуется устанавливаемая `onedir`-сборка:

- пользователь запускает один ярлык или главный `.exe`;
- внутренние библиотеки лежат в каталоге установки;
- запуск быстрее, чем у самораспаковывающегося one-file;
- проще включить драйверы, WebView-компоненты, seabreeze и дополнительные DLL;
- обновление отдельных компонентов предсказуемее.

После аппаратной проверки можно подготовить portable one-file вариант как
дополнительный дистрибутив.

### 10.2. Требования К Установщику

- иконка и сведения о версии;
- ярлык в меню «Пуск» и опционально на рабочем столе;
- установка без консольного окна;
- проверка или установка Evergreen WebView2 Runtime;
- хранение пользовательских настроек вне каталога программы;
- сохранение существующей корневой папки серий;
- корректная работа с кириллицей и длинными путями;
- штатное удаление без удаления данных измерений;
- цифровая подпись после стабилизации сборки.

## 12. Критерии Готовности v2.0

- приложение запускается через собственный `.exe`;
- отдельный браузер и консоль не открываются;
- локальный сервер запускается и завершается автоматически;
- backend недоступен из локальной сети;
- существующие серии открываются без миграции данных;
- результаты измерений совместимы с текущими XLSX и журналом;
- функции текущего модульного приложения доступны в новом интерфейсе;
- live-графики не блокируют измерительный поток;
- frontend можно перезагрузить без потери backend-состояния;
- остановка и закрытие всегда пытаются установить `0 В`;
- камера и измерения корректно завершаются вместе с приложением;
- интерфейс проверен при масштабировании Windows 100–200%;
- пользователь не устанавливает Python или Node.js;
- приложение работает без интернета;
- новая оболочка успешно прошла параллельную проверку с Tkinter-версией.

## 13. Риски

| Риск | Снижение риска |
|---|---|
| Потеря WebSocket во время измерения | Backend хранит состояние; frontend переподключается и запрашивает snapshot |
| Два управляющих окна | Одноразовый токен и единственный активный управляющий клиент |
| Закрытие окна при активном SMU | Отдельный launcher shutdown и подтверждение `0 В` |
| Неупакованные DLL оборудования | Аппаратный proof of concept до переноса всех страниц |
| Антивирус реагирует на one-file | Основной дистрибутив onedir + подписанный установщик |
| Различия WebView2 | Фиксированный минимальный runtime и проверка при установке |
| Перегрузка frontend live-данными | Буферизация и ограничение частоты визуального обновления |
| Расхождение frontend и backend | Версионированные API и схемы WebSocket-событий |
| Случайное изменение форматов данных | Golden-файлы и сравнение результатов с текущей версией |
