# Статус Перехода На v2.0

Дата обновления: 2026-10-01

Рабочая версия: `v2.0.0-alpha`

Стабильная база: `v1.9.1`

## Политика Единого Alpha-Релиза

Весь переход до функционального соответствия накапливается в одном prerelease
`v2.0.0-alpha`.

- версии `alpha-2`, `alpha-3` и подобные не создаются;
- `APP_VERSION` остаётся `2.0.0-alpha` на всех внутренних этапах;
- файл `docs/versions/v2.0.0-alpha.md`, changelog и GitHub Release обновляются
  после каждого опубликованного checkpoint;
- тег `v2.0.0-alpha` передвигается на последний проверенный alpha-commit;
- релиз остаётся prerelease и не помечается latest;
- новая версия создаётся только после завершения перехода или явного решения
  пользователя.

Команды повторной публикации после первого checkpoint:

```powershell
git tag -f v2.0.0-alpha
git push --force oled_app refs/tags/v2.0.0-alpha
.\env\Scripts\python.exe .\scripts\create_github_release.py v2.0.0-alpha --prerelease --latest false --update-existing
```

Сетевые команды выполняются вне sandbox согласно `AGENTS.md`.

## Результат Этапа 1

- `oled_v2_app.py` запускает новый контур отдельно от штатного Tkinter-входа.
- Backend слушает только `127.0.0.1` на случайном порту, проверяет `Host`,
  `Origin`, токен сеанса и допускает один управляющий frontend-клиент.
- React/Vite frontend собирается в `oled_v2/static/`; Node.js не нужен конечному
  пользователю.
- pywebview открывает production frontend в WebView2 с минимальным размером
  `1180×720`.
- `packaging/oled_v2_alpha.spec` создаёт отдельную `onedir`-сборку без консоли;
  smoke-запуск собранного `.exe` пройден.
- Логи v2 ротируются в `%LOCALAPPDATA%\OLED Measurement App\logs` и хранятся
  30 дней.
- Полный набор из 196 автоматических тестов проходит; Tkinter-код и основной
  entrypoint не переключались.

## Результат Программной Части Этапа 2

- Короткий sweep использует существующий simulator/hardware-слой и
  `safe_shutdown_smu`, поэтому отдельная логика управления реальными выходами не
  дублируется.
- Backend допускает только одну активную операцию, передаёт точки по
  аутентифицированному WebSocket и останавливает PoC при закрытии приложения.
- Frontend показывает ток OLED, фототок и спектральный пик в реальном времени,
  а также отдельное подтверждение безопасного отключения выходов.
- Полный sweep и операторский stop визуально проверены в production frontend.
- Исходный и упакованный `--poc-smoke` завершают восемь точек и подтверждают
  безопасный shutdown.
- Пассивный probe на текущем ПК не обнаружил SMU на `COM3` и спектрометр.
  Рабочее напряжение на реальные приборы не подавалось.

## Checkpoint 10 — Начало Stage 5: ВАЯХ На Эмуляторе

- В новом интерфейсе включён пункт `ВАЯХ`: десять параметров, серверная проверка диапазонов и один цикл `SIM_IVL` через существующий `run_ivl_cycle`.
- Backend владеет измерением, хранит точки и состояние; экран получает snapshot каждые 500 мс и восстанавливается после перезагрузки или возвращения из другого раздела.
- Завершённый цикл сохраняет совместимые raw CSV и XLSX в `%LOCALAPPDATA%\OLED Measurement App\simulator_ivl\<run_id>`. При остановке остаётся raw CSV; неполный цикл не выдаётся за готовый результат Excel.
- Отключение SMU выполняется в `finally`, включая ошибку алгоритма; ВАЯХ, PoC и probe взаимно исключены через общий API gate.
- Этап ограничен одним циклом эмулятора: без записи в журнал серии, повторов пробоя и операторских решений; коэффициент светимости фиксирован 1. Формы спектров, стабильности и полная ВАЯХ серии ещё впереди.
- Добавлен `--ivl-smoke` для исходного и упакованного приложения. Сборщик принимает `-PythonPath` для независимого Python-окружения; Visual Studio не нужна для запуска `onedir`.
- Проверены 202 теста, TypeScript/production build, полный цикл 251 точки, восстановление состояния после reload и ручная остановка. Консоль браузера без ошибок и предупреждений.
- Обновлённый onedir прошёл `--backend-smoke`, `--ivl-smoke`, `--poc-smoke`, `--series-smoke` и WebView2 `--window-smoke` с PATH только Windows System32. Чистый Windows-ПК этим не заменён. Интерфейс проверен при 1180×720, общей горизонтальной прокрутки нет.

## Checkpoint 11 — ВАЯХ Выбранного Пикселя Серии

Дата: 2026-09-07.

- Из инспектора серии можно открыть ВАЯХ выбранного пикселя; на экране ВАЯХ доступны все пиксели активной серии и отдельный SIM_IVL.
- Перенесены несколько циклов, пауза и дополнительные подтверждения пробоя. Классификация и формирование XLSX используют существующие функции рабочего приложения.
- Применяется цветовой коэффициент и спектральная модель выбранного пикселя. CSV/XLSX сохраняются по совместимой структуре серии, миниатюра — в общей папке thumbnails, журнал содержит статус, метрики и историю.
- Новый контур пока работает только на эмуляторе. Серийные записи явно помечены `ЭМУЛЯТОР v2` и `hardware_mode=simulator`; проверять следует на тестовых сериях.
- При WORKING без найденного напряжения открытия backend ожидает ручное значение или пропуск; ожидание восстанавливается после reload, SMU уже отключён. Как в Tkinter, ручное значение записывается в журнал, а исходный XLSX сохраняет автоматический результат.
- При NO_CONTACT доступен повтор того же пикселя. Каждый запуск получает отдельный файл, прежние измерения и история сохраняются.
- Смена/редактирование/закрытие серии и её очереди блокируются до завершения ВАЯХ или решения. Повторное и устаревшее решение отвергается.
- Ошибка журнала сохраняет готовые файлы и сообщает об ошибке; при неподтверждённом shutdown успешная запись в журнал не выполняется. Отмена ожидания оставляет файлы без записи в журнал.
- Проверены 214 тестов, production frontend, цикл на 251 точку, восстановление ожидающего решения после reload и сохранение ручного значения с отображением миниатюры и метрик в серии. Ошибок консоли нет.
- `--ivl-smoke` теперь проверяет отдельный и серийный запуск, повторное открытие журнала и миниатюру.
- Пересобранный onedir прошёл backend, IVL, PoC, series и WebView2 window smoke с PATH только Windows System32; production assets в сборке сверены с исходной сборкой frontend.

## Checkpoint 12 — Автоматическая Очередь ВАЯХ Серии

Дата: 2026-09-26.

- Последовательный режим строит очередь от выбранного пикселя в физическом порядке;
  более ранние элементы не возвращаются в очередь.
- Backend хранит текущий пиксель, число завершённых элементов и попыток,
  оставшуюся очередь, пропуски и краткие результаты, поэтому frontend
  восстанавливает операцию после reload.
- Опционально исключаются ранее сохранённые `NONWORKING`/`BURNED`. Для каждого
  оставшегося пикселя отдельно применяются его коэффициент и спектральная
  калибровка, затем сохраняются совместимые CSV/XLSX, миниатюра и журнал.
- После `NO_CONTACT` оператор выбирает повтор, пропуск остатка физической
  подложки или обычное продолжение. Повтор создаёт отдельный файл и историю.
- Остановка сохраняет завершённые результаты и не выдаёт незавершённый цикл за
  журнальную запись; мутации серии остаются заблокированными до завершения.
- Пройдены 220 тестов, production frontend и `--ivl-smoke` с двухпиксельной
  очередью, журналом и миниатюрами.
- Финальный windowed `onedir` прошёл backend, IVL queue, PoC, series и WebView2
  window smoke после отключения консольного formatter Uvicorn.

## Checkpoint 13 — Одиночный Спектр На Эмуляторе

Дата: 2026-09-27.

- В навигации v2 включён пункт `Спектры`; из инспектора серии можно сразу
  передать выбранный пиксель либо выполнить отдельный `SIM_SPECTRUM`.
- Backend валидирует параметры, остаётся владельцем операции и каждые 500 мс
  отдаёт точки, текущую пробу подбора `T_int` и последнюю спектральную кривую.
  После reload или возврата на экран измерение и его состояние сохраняются.
- Используется прежний `run_spectrum_measurement`: электрическая проверка идёт
  до и после каждой пробы интегрирования, результаты записываются через те же
  raw CSV и совместимый XLSX.
- Для пикселя серии можно начинать с журнального напряжения открытия либо с
  ручного значения; применяются его цветовой коэффициент и спектральная модель.
  Итоговые метрики и пометка `ЭМУЛЯТОР v2` сохраняются в прежний журнал.
- При `NO_CONTACT` ложный спектральный файл не создаётся; диагностический XLSX
  для другого электрического ограничения сохраняется явно. Запись журнала
  запрещена, если безопасное отключение SMU не подтверждено.
- Спектр взаимно исключён с ВАЯХ, PoC и probe; изменения активной серии
  блокируются до терминального состояния операции.
- Пройдены 225 тестов, TypeScript, production frontend и `--spectrum-smoke`,
  проверяющий отдельный и серийный запуск, Excel, журнал и safe shutdown.
- Пересобранный windowed `onedir` прошёл backend, PoC, series, IVL, spectrum и
  WebView2 window smoke с кодами завершения `0`.

## Checkpoint 14 — Очередь Спектров Серии

Дата: 2026-09-27.

- Экран спектров поддерживает последовательную съёмку подложки от выбранного
  пикселя и отдельную очередь явно отмеченных пикселей без возврата к более
  ранним позициям.
- Backend владеет очередью, хранит завершённые и оставшиеся пиксели, попытки,
  пропуски и результаты; состояние восстанавливается после reload.
- Перед каждым пикселем требуется решение `измерить`, `пропустить` или
  `остановить`, причём устаревшие и повторные ответы отвергаются.
- После `NO_CONTACT` частичные данные удаляются, а оператор выбирает повтор того
  же пикселя, продолжение или остановку. Повтор получает уникальное имя файла.
- После другого электрического ограничения можно сохранить диагностический
  XLSX либо удалить raw-данные, затем выбрать замену только из той же четверти,
  продолжить очередь или остановиться.
- Пройдены 229 тестов, TypeScript, production frontend и расширенный
  `--spectrum-smoke` с очередью из двух пикселей и проверкой журнала.
- Пересобранный windowed `onedir` прошёл backend, PoC, series, IVL, spectrum и
  WebView2 window smoke; все процессы завершились с кодом `0`.

## Checkpoint 15 — Стабильность На Эмуляторе

Дата: 2026-09-28.

- В навигации v2 включена стабильность для выбранного пикселя серии и отдельного
  `SIM_STABILITY`; из инспектора серии доступен прямой переход.
- Backend владеет операцией и live-точками после reload, поддерживает удержание
  тока с программной обратной связью и прямое удержание напряжения.
- Уставку можно менять во время прогона вводом или шагами `±0.1`, `±0.25`,
  `±0.5`, `±1`; новая цель сохраняется вместе с применённым напряжением.
- В токовом режиме старт можно рассчитать как `0.9 × V` по последней ВАЯХ либо
  задать вручную. Применяются цветовой коэффициент и спектральная калибровка.
- Безопасная остановка создаёт совместимый XLSX из завершённых точек. Серийный
  результат записывается в прежний журнал с пометкой `ЭМУЛЯТОР v2`.
- Добавлена команда `--stability-smoke`; пройдены 234 теста, TypeScript и
  production frontend.
- Пересобранный windowed `onedir` прошёл backend, PoC, series, IVL, spectrum,
  stability и WebView2 window smoke; все процессы завершились с кодом `0`.

Simulator-first контур Stage 5 завершён. Реальное оборудование не включено;
штатный Tkinter-вход остаётся основным до полной parity-проверки.
