# Статус Перехода На v2.0

Дата обновления: 2026-07-31

Рабочая версия: `v2.0.0-alpha`

Стабильная база: `v1.9.1`

## Политика Единого Alpha-Релиза

Весь переход до функционального соответствия накапливается в одном prerelease
`v2.0.0-alpha`.

- версии `alpha-2`, `alpha-3` и подобные не создаются;
- `APP_VERSION` остаётся `2.0.0-alpha` на всех внутренних этапах;
- файл `docs/versions/v2.0.0-alpha.md`, changelog и GitHub Release обновляются
  после каждого опубликованного checkpoint;
- тег `v2.0.0-alpha` передвигается на последний проверенный alpha-commit;
- релиз остаётся prerelease и не помечается latest;
- новая версия создаётся только после завершения перехода или явного решения
  пользователя.

Команды повторной публикации после первого checkpoint:

```powershell
git tag -f v2.0.0-alpha
git push --force oled_app refs/tags/v2.0.0-alpha
.\env\Scripts\python.exe .\scripts\create_github_release.py v2.0.0-alpha --prerelease --latest false --update-existing
```

Сетевые команды выполняются вне sandbox согласно `AGENTS.md`.

## Сохранение Рабочего Приложения

- `oled_modular_app.py` по умолчанию продолжает запускать Tkinter.
- `oled_measurement_app_v2_5.py` не изменяется в рамках миграции.
- v2 будет добавляться отдельным launcher/backend/frontend-контуром.
- Переключение основного входа возможно только после этапа 9, проверки на
  оборудовании и отдельного решения пользователя.

## Результат Этапа 1

- `oled_v2_app.py` запускает новый контур отдельно от штатного Tkinter-входа.
- Backend слушает только `127.0.0.1` на случайном порту, проверяет `Host`,
  `Origin`, токен сеанса и допускает один управляющий frontend-клиент.
- React/Vite frontend собирается в `oled_v2/static/`; Node.js не нужен конечному
  пользователю.
- pywebview открывает production frontend в WebView2 с минимальным размером
  `1180×720`.
- `packaging/oled_v2_alpha.spec` создаёт отдельную `onedir`-сборку без консоли;
  smoke-запуск собранного `.exe` пройден.
- Логи v2 ротируются в `%LOCALAPPDATA%\OLED Measurement App\logs` и хранятся
  30 дней.
- Полный набор из 175 автоматических тестов проходит; Tkinter-код и основной
  entrypoint не переключались.

## Результат Программной Части Этапа 2

- Короткий sweep использует существующий simulator/hardware-слой и
  `safe_shutdown_smu`, поэтому отдельная логика управления реальными выходами не
  дублируется.
- Backend допускает только одну активную операцию, передаёт точки по
  аутентифицированному WebSocket и останавливает PoC при закрытии приложения.
- Frontend показывает ток OLED, фототок и спектральный пик в реальном времени,
  а также отдельное подтверждение безопасного отключения выходов.
- Полный sweep и операторский stop визуально проверены в production frontend.
- Исходный и упакованный `--poc-smoke` завершают восемь точек и подтверждают
  безопасный shutdown.
- Пассивный probe на текущем ПК не обнаружил SMU на `COM3` и спектрометр.
  Рабочее напряжение на реальные приборы не подавалось.

## Результат Этапа 3

- Токены и общие React-компоненты находятся в
  `v2_frontend/src/design-system/`, а не дублируются по будущим экранам.
- Эталон серии показывает рабочую плотность таблицы, семантические статусы,
  фильтры, иерархию действий, график, toast и блокирующий stop-диалог.
- Макет не подключён к series API и гарантированно не меняет пользовательские
  файлы; это визуальный контракт для Stage 4.
- При `1366×768` и `1180×720` страница не получает горизонтальную прокрутку;
  таблица остаётся читаемой и при необходимости прокручивается внутри.
- После рефакторинга Stage 2 повторно завершил 32-точечный sweep, сохранил
  WebSocket/live-график/safe stop и не выдал ошибок консоли.

## Результат Этапа 4

- `oled_v2/series_service.py` сериализует существующие `SeriesManager` и
  `SeriesJournal` в API, не вводя новый формат серии и не переписывая журнал.
- Доступны выбор корня, список до 200 найденных серий, ручное открытие папки,
  создание, закрытие, редактирование и обновление открытой серии.
- Рабочая область показывает все 48 пикселей и 12 подложек в физическом порядке,
  метрики и статусы, последние данные, до пяти дат истории ВАЯХ и миниатюру.
- Очередь спектров изменяется для отдельного неизмеренного пикселя или всей его
  подложки; уже снятый спектр не заменяется флажком.
- Создание/редактирование, очередь и повторное открытие проверены через
  production frontend на изолированной серии. Синтетическая ВАЯХ подтвердила
  историю, статус и защищённую загрузку миниатюры.
- Исходный и упакованный `--series-smoke` проверяют XLSX-журнал, 48 пикселей,
  очередь подложки и её сохранность после повторного открытия.
- При `1366×768` и `1180×720` общей горизонтальной прокрутки нет, ошибки и
  предупреждения консоли отсутствуют.

## Подтверждённые Решения

Перед этапом 1 подтверждён следующий набор:

- графики — Apache ECharts;
- Windows — Windows 10 22H2 и Windows 11;
- дистрибутив до аппаратной проверки — только `onedir`, без portable one-file;
- светлая тема, без тёмной темы в первом v2.0;
- минимальное окно — `1180×720`, рабочий минимум экрана — `1366×768`;
- автоматические обновления не включать в первый v2.0;
- production-логи — `%LOCALAPPDATA%\OLED Measurement App\logs`, ротация по
  размеру, хранение 30 дней;
- для лабораторной проверки составить отдельный список ПК, драйверов и версий
  ПО перед этапом 8.

## Следующий Шаг

Stage 5: подключить формы ВАЯХ, спектров и стабильности, общий preflight и экран
активного измерения к существующим Python workflow. Backend должен оставаться
владельцем операции и восстанавливать состояние frontend после переподключения.
Реальная аппаратная проверка остаётся обязательной до этапа 9 и переключения
основного входа, но не блокирует simulator-first программную работу.
