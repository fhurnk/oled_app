# v2.0.0-alpha

Дата первого checkpoint: 2026-07-30

Дата последнего checkpoint: 2026-08-21

Канал: prerelease

Стабильная база: `v1.9.1`

## Политика Alpha

Все этапы перехода на v2 накапливаются в одном GitHub Release и теге
`v2.0.0-alpha`. Отдельные версии `alpha-2`, `alpha-3` и последующие не создаются.
Этот файл, changelog, тег и prerelease обновляются после каждого проверенного
checkpoint до завершения перехода или отдельного решения пользователя.

Рабочее Tkinter-приложение остаётся штатным:

- `oled_modular_app.py` продолжает быть основным входом;
- `oled_measurement_app_v2_5.py` остаётся нетронутым референсом;
- будущие launcher/backend/frontend v2 добавляются отдельным контуром;
- переключение основного входа запрещено до функционального соответствия,
  аппаратной проверки и отдельного решения пользователя.

## Checkpoint 1 — Фиксация Поведения

- Начато выполнение `docs/v2_interface_plan.md`.
- Добавлен `docs/v2_functional_parity_checklist.md` с матрицей всех рабочих
  экранов и действий v1.9.1.
- Зафиксированы значения по умолчанию основных и расширенных параметров ВАЯХ,
  спектров, стабильности, камеры, оборудования, единиц и хранения raw CSV.
- Описаны переходы между экранами, условия доступности workflow, ошибки и решения
  оператора для `NO_CONTACT`, `CURRENT_LIMIT`, ручного opening voltage,
  стабильности, камеры и безопасной остановки.
- Зафиксированы совместимые контракты `series_config.json`,
  `series_journal.xlsx`, raw CSV и итоговых XLSX.
- Определены 12 golden-сценариев для сравнения Tkinter и v2 без добавления
  пользовательских серий измерений в git.
- Добавлен `docs/v2_migration_status.md` с этапами, защитой основного приложения и
  решениями, которые нужно подтвердить перед техническим прототипом.

## Checkpoint 2 — Технический Прототип

- Добавлен отдельный `oled_v2_app.py`; штатный `oled_modular_app.py` продолжает
  запускать Tkinter.
- Реализован FastAPI backend на случайном порту `127.0.0.1` с lifecycle,
  session token, проверкой `Host`/`Origin` и одним управляющим клиентом.
- Реализован светлый React/Vite-экран обзора, который читает версию, состояние
  backend, режим оборудования и статус миграции.
- Production assets собираются в `oled_v2/static/` и входят в desktop-сборку,
  поэтому Node.js не требуется на лабораторном ПК.
- pywebview открывает frontend в отдельном WebView2-окне с минимальным размером
  `1180×720`.
- Добавлены ротация логов в `%LOCALAPPDATA%\OLED Measurement App\logs`,
  `requirements-v2.txt`, build-скрипты и PyInstaller `onedir`-спецификация.
- Подготовлена и проверена отдельная `onedir`-сборка размером 24 МБ. Основной
  Tkinter-дистрибутив и reference-файл не переключались.

## Checkpoint 3 — Аппаратный PoC На Эмуляторе

- Backend получил отдельный координатор короткой операции SMU и спектрометра,
  построенный поверх существующих `oled_app.hardware`-адаптеров.
- Первый PoC намеренно работает только в эмуляторе, ограничен 8 мА, не открывает
  пользовательскую серию и не создаёт CSV/XLSX.
- Точки напряжения, тока OLED, фототока и спектрального пика передаются во
  frontend через аутентифицированный WebSocket с lease одного клиента.
- React-экран показывает live-график Apache ECharts, телеметрию, состояние
  операции и подтверждение безопасного отключения выходов.
- Доступны запуск эмулятора, операторская остановка и пассивная проверка
  текущих приборов без подачи рабочего напряжения.
- Добавлен полный `--poc-smoke` для проверки исходного и упакованного контура.
- Программная часть этапа 2 подтверждена. Реальная аппаратная проверка ожидает
  подключения стенда и не считается завершённой этим checkpoint.

## Checkpoint 4 — Дизайн-Система И Эталон Серии

- В `v2_frontend/src/design-system/` вынесены семантические токены цветов,
  размеров, отступов, скруглений, теней, анимаций и графиков.
- Добавлены переиспользуемые React-компоненты кнопок, полей, панелей, статусов,
  уведомлений, toast и блокирующего диалога.
- Пункт `Серия` открывает визуальный эталон Stage 3 с фильтрами, таблицей
  пикселей, состояниями, графиком и примером безопасной остановки.
- Эталон не обращается к series API, не открывает пользовательские папки и не
  записывает файлы; реальная работа с сериями начинается на Stage 4.
- Компоновка проверена при `1366×768` и `1180×720`; таблица прокручивается
  только внутри, горизонтальной прокрутки всей страницы нет.
- После рефакторинга повторно пройден полный 32-точечный PoC без ошибок
  консоли. Реальная аппаратная приёмка остаётся пунктом итогового чек-листа.

## Checkpoint 5 — Рабочее Пространство Серии

- Добавлен `oled_v2/series_service.py`, который использует существующие
  `SeriesManager` и `SeriesJournal` без миграции `series_config.json` или XLSX.
- Защищённые API поддерживают корень и список серий, создание, открытие,
  закрытие, редактирование, обновление, очередь спектров и получение миниатюры.
- `SeriesWorkspace.tsx` заменил визуальный эталон: доступны стартовая страница,
  форма четырёх четвертей, метрики, карта 48 пикселей, таблица, история ВАЯХ и
  инспектор выбранного пикселя.
- Очередь спектров можно менять для одного пикселя или всех неизмеренных
  пикселей выбранной подложки; флажок не показывается после снятого спектра.
- Production UI проверен на изолированной серии: создание, редактирование,
  повторное открытие, сохранение очереди, синтетическая история и миниатюра.
- Добавлен `--series-smoke` для проверки совместимого XLSX-журнала, 48 пикселей
  и повторного открытия очереди из исходного и упакованного backend.
- При `1366×768` и `1180×720` страница не получает горизонтальную прокрутку;
  ошибок и предупреждений консоли нет.
- Измерительные workflow остаются задачей Stage 5, а штатный Tkinter-вход не
  переключался.

## Checkpoint 6 — Неблокирующее Открытие Больших Серий

- Открытие серии в штатном Tkinter-приложении больше не строит все отсутствующие
  миниатюры ВАЯХ в главном потоке.
- Кнопка `Обновить` запускает полную проверку миниатюр в фоновом потоке; наведение
  без готового превью запускает фоновую подготовку одного пикселя и показывает
  краткий статус вместо зависшего окна.
- Недостающие метрики старых спектральных XLSX читаются в фоне, кэшируются на время
  сеанса и подставляются в таблицу после загрузки.
- Исправление проверено на пользовательской серии `2026-07-29_Blue`, где медленная
  гидратация файлов OneDrive последовательно блокировала создание 34 миниатюр и
  чтение 6 спектральных книг.

## Checkpoint 7 — Устойчивая Классификация И Очередь ВАЯХ

- `WORKING` теперь требует устойчивого превышения порога рабочего фототока;
  количество следующих подтверждающих точек задаётся независимо от параметров
  напряжения открытия.
- Одиночный всплеск фототока больше не переводит пиксель в рабочий статус.
- В последовательной ВАЯХ добавлен сохраняемый флажок пропуска пикселей с
  журнальным статусом `NONWORKING`; `NO_CONTACT` остаётся доступным для пересъёмки.
- Ручной выбор произвольного пикселя перестраивает оставшуюся очередь и продолжает
  последовательность со следующего пикселя от новой позиции.
- Новые параметры подтверждения сохраняются в итоговой книге ВАЯХ.
