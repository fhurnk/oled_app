# Версия v1.8.0-alpha

Дата начала: 2026-07-15

Статус: единая экспериментальная GitHub prerelease, не стабильный релиз.

## Политика alpha-версии

Все изменения текущего этапа интеграции камеры накапливаются в `v1.8.0-alpha`. Отдельные версии `alpha.1`, `alpha.2`, `alpha.3` и последующие не создаются: файл, тег и GitHub Release `v1.8.0-alpha` всегда должны описывать самое актуальное состояние alpha-сборки.

## Смысл версии

`v1.8.0-alpha` добавляет изолированный этап работы с Canon через Raspberry Pi. Цель — проверить управление камерой, LiveView, фото и видео без VNC Viewer до интеграции с ВАЯХ и Ossila.

## Добавлено

- Кнопка `Камера (alpha)` на стартовом экране и в меню открытой серии.
- Отдельное неблокирующее Tk-окно состояния камеры, LiveView, фото, видео и файлов.
- Сохраняемые настройки IP/имени Raspberry Pi, порта, тайм-аутов и папки загрузки.
- Dependency-free HTTP-клиент на стороне основного приложения; Pillow используется только для отображения JPEG LiveView.
- FastAPI-сервис Raspberry Pi с API состояния, инициализации, LiveView, preview-снимка, полноразмерного фото, видео и скачивания файлов.
- Пример `systemd`-службы и отдельная инструкция установки.
- Проектная заметка `docs/camera_quality_research.md` о выборе качества по возможностям подключённой камеры; API и интерфейс качества пока не реализованы.

## Организация LiveView и видео

Сервис запускает один процесс `gphoto2 --stdout --capture-movie`. Полученные JPEG-кадры одновременно доступны HTTP-клиенту и, при записи, передаются в `ffmpeg` через `stdin`. Это сохраняет LiveView во время записи и уменьшает число перезапусков Canon.

FFmpeg получает временные метки по времени поступления кадров и пишет VFR-видео H.264 без искусственно заданного FPS. MP4 сначала имеет окончание `.part`, затем проверяется через `ffprobe` и только после успешной проверки переносится в каталог готовых видео.

## Исправлено

- JPEG полностью загружается из памяти до передачи изображения в Tk, поэтому ленивый декодер Pillow больше не зависит от уже закрытого временного потока.
- `ImageTk.PhotoImage` явно использует Tcl-интерпретатор canvas окна камеры.
- При отказе `LANCZOS` для отдельного кадра масштабирование повторяется через `BILINEAR`.
- Повторяющаяся ошибка одного этапа выводится один раз и затем через каждые 50 повторов вместо записи в лог на каждом кадре; диагностика различает декодирование JPEG и отрисовку Tk.
- `CameraClient` хранит активный HTTP-ответ LiveView и может принудительно закрыть его из управляющего потока.
- Закрытие потока выполняется при остановке LiveView, повторном подключении и закрытии окна камеры.
- Окно камеры ожидает завершения фонового потока до одной секунды и не запускает замену, пока прежний поток ещё работает.
- При остановке удаляются кадры, оставшиеся в локальной очереди.
- Обработчик каждого соединения использует собственный `Event`, исключая гонку со следующим подключением.

## Проверено программно

- компиляция Python-модулей;
- импорт основного GUI и alpha-окна камеры;
- unit-тесты выделения JPEG-кадров, URL, безопасных имён файлов и принудительного закрытия заблокированного HTTP-чтения;
- запуск локального FastAPI-сервиса и ответы `/api/health` и `/api/camera/status`;
- декодирование реального сохранённого preview JPEG `1024×680` и создание `ImageTk.PhotoImage` в Windows;
- единый JSON-ответ `DEPENDENCY_NOT_FOUND`, когда в тестовой Windows-среде отсутствует `gphoto2`;
- status-smoke модульного приложения.

## Требует проверки на оборудовании

- освобождение конкретной Canon от GVFS;
- многократные циклы LiveView → остановка → LiveView;
- переподключение к перезапущенному systemd-сервису без перезапуска Windows-приложения;
- полноразмерное фото с автоматическим восстановлением LiveView;
- кодирование и `ffprobe` MP4 на используемой модели Raspberry Pi;
- длительная стабильность и 20 последовательных циклов LiveView → фото → LiveView → видео;
- отсутствие задержек команд после потери и восстановления Raspberry Pi.

## Ограничения

- Нет связи с измерениями, пробоем, журналом серии или идентификатором пикселя.
- LiveView является preview-потоком gPhoto2 и может отличаться от внутреннего видеорежима Canon по разрешению и FPS.
- Выбор качества фото и видео пока не реализован.
- API предназначен только для доверенной локальной сети и пока не имеет авторизации.
