# Версия v1.8.0-alpha

Дата начала: 2026-07-15

Статус: единая экспериментальная GitHub prerelease, не стабильный релиз.

## Политика alpha-версии

Все изменения текущего этапа интеграции камеры накапливаются в `v1.8.0-alpha`. Отдельные версии `alpha.1`, `alpha.2`, `alpha.3` и последующие не создаются: файл, тег и GitHub Release `v1.8.0-alpha` всегда должны описывать самое актуальное состояние alpha-сборки.

## Смысл версии

`v1.8.0-alpha` добавляет изолированный этап работы с Canon через Raspberry Pi. Цель — проверить управление камерой, LiveView, фото и видео без VNC Viewer до интеграции с ВАЯХ и Ossila.

## Добавлено

- Поле `Название снимка` для пользовательского имени сохраняемого кадра LiveView или полноразмерного фото.
- Безопасная передача имени в Raspberry Pi API, автоматическое расширение `.jpg` и числовые суффиксы при повторном использовании имени без перезаписи файлов.
- Кнопка `Камера (alpha)` на стартовом экране и в меню открытой серии.
- Отдельное неблокирующее Tk-окно состояния камеры, LiveView, фото, видео и файлов.
- Сохраняемые настройки IP/имени Raspberry Pi, порта, тайм-аутов и папки загрузки.
- Dependency-free HTTP-клиент на стороне основного приложения; Pillow используется только для отображения JPEG LiveView.
- FastAPI-сервис Raspberry Pi с API состояния, инициализации, LiveView, preview-снимка, полноразмерного фото, видео и скачивания файлов.
- Пример `systemd`-службы и отдельная инструкция установки.
- Динамический выбор безопасных JPEG-вариантов, которые подключённая камера сообщает через gPhoto2.
- Раздельный выбор качества/размера LiveView и FPS из вариантов, которые фактически сообщает подключённая камера; недоступные настройки явно отключаются.
- Флажок `Оставлять файл на Raspberry Pi после скачивания`; при снятом флажке исходник удаляется только после проверки локального файла.
- API `/api/camera/capabilities` и `DELETE /api/files/{file_id}`.
- Проектная заметка `docs/camera_quality_research.md` о решениях и ограничениях выбора качества.
- Примеры установки и systemd-служба для Linux-пользователя `user` с каталогом `/home/user/oled-camera`.
- Настраиваемый центральный кроп ширины и высоты от 1 до 100%, общий для LiveView, preview-снимка, полноразмерного фото и MP4.

## Организация LiveView и видео

Сервис запускает один процесс `gphoto2 --stdout --capture-movie`. Полученные JPEG-кадры одновременно доступны HTTP-клиенту и, при записи, передаются в `ffmpeg` через `stdin`. Это сохраняет LiveView во время записи и уменьшает число перезапусков Canon.

FFmpeg получает временные метки по времени поступления кадров и пишет VFR-видео H.264 без искусственно заданного FPS. Степень сжатия задаётся одним серверным `ffmpeg_crf` в конфигурации Raspberry Pi, а не пользовательскими «профилями». MP4 сначала имеет окончание `.part`, затем проверяется через `ffprobe` и только после успешной проверки переносится в каталог готовых видео.

## Исправлено

- Статус точки спектра теперь рассчитывается по raw-интенсивности, которая использовалась при подборе экспозиции. Вычитание фона больше не превращает уже принятый спектр из `GOOD` в ложный `TOO_WEAK`; журнал показывает только raw-пик и raw-статус, а summary raw CSV хранит raw-пик в отдельных столбцах.
- Найденное время интегрирования переносится на следующую точку независимо от того, больше оно или меньше 10 мс. При raw-интенсивности выше цели следующее стартовое время автоматически уменьшается пропорционально превышению, снижая риск насыщения.
- В настройках времена интегрирования отображаются в миллисекундах и добавлен флажок переноса `T_int` предыдущей точки; внутренний формат настроек в секундах сохранён для совместимости.
- Автоматическая проверка USB-спектрометра изолирована в отдельном дочернем процессе с тайм-аутом 5 секунд. Если SeaBreeze зависает при опросе уже подключённого прибора, главное окно остаётся отзывчивым и показывает предупреждение вместо зависания.
- Классификация `TOO_WIDE` удалена из съёмки спектров: большая FWHM больше не удерживает подбор времени интегрирования на текущей точке. Максимальная FWHM убрана из настроек, но измеренное значение ширины пика по-прежнему сохраняется для анализа.
- Клиентский тайм-аут остановки LiveView увеличен относительно максимального серверного времени `SIGINT → terminate → kill`, поэтому уже выполненная остановка не отображается как потеря соединения.
- HTTP-генератор LiveView проверяет отключение клиента и освобождает ожидающую задачу не позднее одной секунды; остановка gPhoto2 немедленно будит все ожидающие потоки.
- Оставшийся после аварийного закрытия desktop-приложения LiveView автоматически останавливается через две секунды после отключения последнего клиента.
- После остановки сервис ожидает reader/stderr-потоки gPhoto2 и закрывает pipe-дескрипторы, предотвращая накопление ресурсов при большом числе циклов LiveView.
- Закрытие главного приложения гарантированно запускает очистку окна камеры, локального потока и удалённого LiveView.
- В статус и окно камеры добавлен счётчик активных LiveView-клиентов для диагностики оставшихся экземпляров приложения.
- После остановки потока сервис явно задаёт `0` реальному параметру gPhoto2 `viewfinder`/`eosviewfinder`, считывает его обратно и передаёт результат проверки в окно камеры.
- Нижний журнал удалён из окна камеры; последняя операция перенесена в состояние, а сведения об источнике сокращены до разрешения, FPS и размера после кропа.
- LiveView увеличивается до заполнения ширины или высоты canvas, список файлов расположен под изображением слева, а предпочтительная высота окна снижена до 720 логических пикселей.
- При отключении Raspberry Pi от сети отложенный обработчик статуса больше не обращается к уже удалённой переменной исключения и не завершает приложение.
- Потерянное соединение теперь явно переводит окно в состояние `Связь потеряна`, останавливает локальный поток и оставляет возможность подключиться повторно без перезапуска приложения.
- Главное окно и окно камеры учитывают системный DPI Windows и ограничиваются доступной областью экрана.
- Правая панель камеры прокручивается, поэтому состояние, настройки, кнопки и список файлов остаются доступны при небольшой высоте экрана ноутбука.
- JPEG полностью загружается из памяти до передачи изображения в Tk, поэтому ленивый декодер Pillow больше не зависит от уже закрытого временного потока.
- `ImageTk.PhotoImage` явно использует Tcl-интерпретатор canvas окна камеры.
- При отказе `LANCZOS` для отдельного кадра масштабирование повторяется через `BILINEAR`.
- Повторяющаяся ошибка одного этапа выводится один раз и затем через каждые 50 повторов вместо записи в лог на каждом кадре; диагностика различает декодирование JPEG и отрисовку Tk.
- `CameraClient` хранит активный HTTP-ответ LiveView и может принудительно закрыть его из управляющего потока.
- Закрытие потока выполняется при остановке LiveView, повторном подключении и закрытии окна камеры.
- Окно камеры ожидает завершения фонового потока до одной секунды и не запускает замену, пока прежний поток ещё работает.
- При остановке удаляются кадры, оставшиеся в локальной очереди.
- Обработчик каждого соединения использует собственный `Event`, исключая гонку со следующим подключением.

## Требует проверки на оборудовании

- соответствие raw-статуса и результата подбора экспозиции на образце с заметным фоном;
- перенос найденного `T_int` между соседними точками при экспозициях выше и ниже 10 мс и снижение старта после интенсивного спектра;
- запуск приложения с уже подключённым спектрометром и корректность его статуса после изолированной проверки SeaBreeze;
- последовательная съёмка спектров слабосветящихся образцов без задержки на бывшем статусе `TOO_WIDE`;
- освобождение конкретной Canon от GVFS;
- многократные циклы LiveView → остановка → LiveView;
- переподключение к перезапущенному systemd-сервису без перезапуска Windows-приложения;
- полноразмерное фото с автоматическим восстановлением LiveView;
- кодирование и `ffprobe` MP4 на используемой модели Raspberry Pi;
- совпадение выбранного центрального кропа в LiveView, JPEG и MP4 на реальной камере;
- длительная стабильность и 20 последовательных циклов LiveView → фото → LiveView → видео;
- отсутствие задержек команд после потери и восстановления Raspberry Pi.

## Ограничения

- Нет связи с измерениями, пробоем, журналом серии или идентификатором пикселя.
- LiveView является preview-потоком gPhoto2 и может отличаться от внутреннего видеорежима Canon по разрешению и FPS.
- Некоторые камеры не экспортируют управление FPS либо предоставляют качество и FPS только как единый режим; приложение не разделяет то, что нельзя независимо переключить в API камеры.
- RAW/RAW+JPEG пока не предлагаются, поскольку текущая операция ожидает один JPEG-файл.
- API предназначен только для доверенной локальной сети и пока не имеет авторизации.
