# История Обновлений

## v1.6.0 - 2026-06-25

### Изменено

- Подбор `T_int` в спектрах работает по старой схеме до насыщения первой пробы на 10 мс; после такого насыщения следующие точки стартуют с найденного безопасного времени.
- Окна ВАЯХ, спектров и стабильности запоминают последние параметры измерения, включая конечное напряжение, шаг и предел тока.
- Спектральное измерение больше не перезаписывает статус работоспособности элемента; рабочий статус берётся из ВАЯХ или стабильности.
- Сохранение спектральной книги выполняется реже во время съёмки, чтобы уменьшить торможение после нескольких точек.
- Окно live-спектра показывает положение и значение максимума интенсивности.
- На карте статусов подложки нижних четвертей подняты выше, чтобы не закрывать легенду.
- Нижняя лог-консоль в меню измерений убрана, освобождая место для таблицы измерений.

### Добавлено

- В `oled_app_settings.json` сохраняются последние основные параметры измерений для ВАЯХ, спектров и стабильности.

## v1.5.6 - 2026-06-25

### Добавлено

- Добавлен `CODEX_PROJECT.md`: короткая карта проекта, которую будущий чат Codex должен читать первой.
- Добавлен `docs/project_manifest.json`: структурированный manifest с текущей версией, ключевыми файлами, правилами релизов и локальными исключениями.

### Изменено

- `AGENTS.md` теперь явно задаёт порядок чтения файлов для новых чатов Codex.
- Правила версии требуют обновлять `CODEX_PROJECT.md` и `docs/project_manifest.json` вместе с `README.md`, `PROJECT_OVERVIEW.md`, `CHANGELOG.md` и `docs/versions/`.
- Версия приложения обновлена до `v1.5.6`.

## v1.5.5 - 2026-06-25

### Добавлено

- Добавлен скрипт `scripts/create_github_release.py` для создания GitHub Release по тегу версии и файлу `docs/versions/vX.Y.Z.md`.
- Скрипт умеет использовать GitHub CLI, если он установлен, или GitHub REST API через `GITHUB_TOKEN` / `GH_TOKEN`.

### Изменено

- Инструкции `AGENTS.md` и `docs/GITHUB_RELEASE_WORKFLOW.md` обновлены так, чтобы будущие чаты Codex могли создавать релизы командой из репозитория.
- Версия приложения обновлена до `v1.5.5`.

## v1.5.4 - 2026-06-25

### Добавлено

- Добавлены инструкции `AGENTS.md` для будущих чатов Codex: обновление версии, `CHANGELOG.md`, `docs/versions/`, commit, tag и GitHub Release для каждой версии.
- Добавлен документ `docs/GITHUB_RELEASE_WORKFLOW.md` с порядком публикации версий и релизов.

### Изменено

- При съёмке спектров успешно подобранное время интегрирования становится стартовым для следующей точки, в том числе если первая проба была saturated.
- Выбранный режим live-графика ВАЯХ (`I / ФД` или `J / L`) сохраняется в настройках и используется при следующем измерении.
- Дополнительные окна приложения автоматически подгоняют стартовый размер под содержимое, чтобы элементы были видны без ручного растягивания.
- Версия приложения обновлена до `v1.5.4`.

## v1.5.3 - 2026-06-25

### Исправлено

- Исправлена классификация ВАЯХ: если пиксель не светит и достигает обычного лимита тока, но не достигает порога пробоя/сгорания, ему присваивается `NONWORKING`, а не `BURNED`.
- Финальный статус и описание первого промера больше не считают сам факт аварийной остановки по лимиту тока сгоранием пикселя.

### Изменено

- Статус `BURNED` теперь ставится только при достижении порога `Ток пробоя/сгорания, мА`.
- Версия приложения обновлена до `v1.5.3`.

## v1.5.2 - 2026-06-25

### Добавлено

- Переключатель live-графика ВАЯХ:
  - `I / ФД` для тока OLED и фототока;
  - `J / L` для плотности тока и светимости.
- Учёт площади пикселя в `мм^2`.
- Коэффициент перевода фототока `мкА -> кд/м^2`.
- Вывод плотности тока `mA/cm^2`.
- Вывод светимости `cd/m^2`.
- Документация проекта:
  - `README.md`;
  - `PROJECT_OVERVIEW.md`;
  - `CHANGELOG.md`;
  - `docs/versions/v1.5.2.md`.
- `.gitignore`, исключающий `OLED_series/` и локальные рабочие файлы.

### Изменено

- Версия приложения обновлена до `v1.5.2`.
- Для папок измерений используется нейминг вида `CR1/CR1_1/CR1_1_1`.
- Спектральная обработка использует raw-спектр.
- Фон спектра считается как среднее значение короткого плоского участка raw-спектра.
- `Dark corrected` оставлен как диагностический лист, но не участвует в основной обработке.

### Исправлено

- После статуса `BURNED` запускается дополнительный подтверждающий цикл.
- При съёмке серии окно выбора ВАЯХ закрывается перед стартом.
- Выбор произвольного пикселя в режиме серии используется как стартовая точка.
- Большой круг с карты подложкодержателя убран.
