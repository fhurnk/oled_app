# История Обновлений

## v1.7.5 - 2026-07-02

### Добавлено

- Добавлен общий модуль `oled_app/measurements/raw_io.py` для построчной записи raw CSV с flush после каждой точки измерения.
- Добавлен пакет `oled_app/processing/` и модуль `ivl_results.py`, который собирает совместимый итоговый `IVL_*.xlsx` из raw CSV.
- Добавлен модуль `oled_app/processing/spectrum_results.py`, который собирает совместимый итоговый `SPECTRUM_*.xlsx` из raw summary/spectra CSV.
- Добавлен модуль `oled_app/processing/stability_results.py`, который собирает совместимый итоговый `STABILITY_*.xlsx` из raw CSV.
- В настройках появился пункт `Сырые CSV после обработки`: raw-файлы можно сохранять в подпапке `raw_data` или удалять после успешной сборки XLSX.

### Изменено

- Модульная ВАЯХ теперь пишет `IVL_<pixel>_<timestamp>_raw.csv` во время измерения и только после завершения собирает итоговый `IVL_<pixel>_<timestamp>.xlsx`.
- Модульная съемка спектров теперь пишет `SPECTRUM_<pixel>_<timestamp>_summary_raw.csv` и `SPECTRUM_<pixel>_<timestamp>_spectra_raw.csv` во время измерения и только после завершения собирает итоговый `SPECTRUM_<pixel>_<timestamp>.xlsx`.
- Модульная стабильность теперь пишет `STABILITY_<pixel>_<current>mA_<timestamp>_raw.csv` во время измерения и только после завершения собирает итоговый `STABILITY_<pixel>_<current>mA_<timestamp>.xlsx`.
- Журнал серии и `result["file"]` по-прежнему указывают на итоговый `.xlsx`; raw CSV остается рабочим/восстановительным форматом и не заменяет внешний контракт приложения.
- `docs/raw_csv_measurement_pipeline_plan.md` отмечает выполненные этапы перехода: общий raw-слой, перенос IVL, Spectrum и Stability.

## v1.7.4 - 2026-07-02

### Изменено

- Имя файла отчета по умолчанию теперь строится по выбранным датам ВАЯХ и спектров: одна дата при совпадении или `IVL_<date>_Spctr_<date>` при разных датах.
- COM-порт убран из основного окна ВАЯХ; измерение берет порт из общих настроек или авто-COM.
- Сохранение настроек больше не переводит приложение на стартовый экран, а оставляет пользователя в текущем окне.

### Исправлено

- Вложенные таблицы в меню измерений OLED теперь перехватывают колесо мыши сами, поэтому история ВАЯХ и таблица последних дат/метрик прокручиваются независимо от основного окна.
- Прокрутка колесом в неперемещаемых областях больше не вызывает ошибку Tk `invalid command name`, если предыдущий canvas уже закрыт.

## v1.7.3 - 2026-07-02

### Исправлено

- На стартовый экран модульного GUI возвращена панель состояния оборудования с автоматической проверкой SMU/спектрометра.
- В общих прокручиваемых окнах модульного GUI восстановлена прокрутка колесом мыши при наведении на область содержимого.
- В подготовке Origin-отчета ВАЯХ порядок IVL-кривых теперь определяется номером четверти, подложки и пикселя, а не строковой сортировкой имен.
- После построения графиков Origin отчет явно пересобирает легенду, чтобы в ней отображались все добавленные кривые.

- `OLEDModularApp` теперь открывает перенесенное окно настроек вместо временной заглушки.
- `OLEDModularApp` теперь открывает перенесенное окно ВАЯХ и вызывает workflow `oled_app.measurements.ivl.run_ivl_measurement`.

- `OLEDModularApp` теперь открывает перенесенное окно отчета и запускает совместимую CLI-оболочку `scripts/build_report_origin_workbook.py`.

## v1.7.1 - 2026-06-29

- Строка статуса оборудования теперь показывает только понятные состояния Ossila/xtralien и спектрометра без технического текста исключений.

## v1.7.0 - 2026-06-29

### Добавлено

- В меню серии добавлена кнопка `Составить отчет`, запускающая подготовку Origin-отчета по папке `measurements`.
- В окне отчета можно выбрать спектральный пиксель для каждой подсерии, если в ней снято несколько пикселей.
- Для отчета добавлены поля начала, конца и шага напряжения: общий режим применяет одну сетку ко всем выбранным пикселям, индивидуальный режим задает сетку для каждого пикселя.
- Отчетный скрипт поддерживает фильтрацию спектров по общей сетке и аргумент `--spectrum-voltage-grid PIXEL=START:STOP:STEP` для индивидуальных сеток.
- При достижении лимита тока во время съемки спектра пиксель получает статус `NEEDS_REVIEW` (`требует уточнения`) и оранжевую заливку на карте статусов.

### Изменено

- Общие спектральные графики отчета строятся на максимальном напряжении, которое присутствует у всех выбранных пикселей после фильтрации.
- При выборе общей сетки отчет ограничивает значения только напряжениями, существующими во всех выбранных спектрах.

### Исправлено

- Верхние четверти на карте подложкодержателя подняты выше, чтобы не наезжать на нижние подложки.

## v1.6.0 - 2026-06-25

### Изменено

- Подбор `T_int` в спектрах работает по старой схеме до насыщения первой пробы на 10 мс; после такого насыщения следующие точки стартуют с найденного безопасного времени.
- Окна ВАЯХ, спектров и стабильности запоминают последние параметры измерения, включая конечное напряжение, шаг и предел тока.
- Спектральное измерение больше не перезаписывает статус работоспособности элемента; рабочий статус берётся из ВАЯХ или стабильности.
- Сохранение спектральной книги выполняется реже во время съёмки, чтобы уменьшить торможение после нескольких точек.
- Окно live-спектра показывает положение и значение максимума интенсивности.
- На карте статусов подложки нижних четвертей подняты выше, чтобы не закрывать легенду.
- Нижняя лог-консоль в меню измерений убрана, освобождая место для таблицы измерений.

### Добавлено

- В `oled_app_settings.json` сохраняются последние основные параметры измерений для ВАЯХ, спектров и стабильности.

## v1.5.2 - 2026-06-25

### Добавлено

- Переключатель live-графика ВАЯХ:
  - `I / ФД` для тока OLED и фототока;
  - `J / L` для плотности тока и светимости.
- Учёт площади пикселя в `мм^2`.
- Коэффициент перевода фототока `мкА -> кд/м^2`.
- Вывод плотности тока `mA/cm^2`.
- Вывод светимости `cd/m^2`.
- Документация проекта:
  - `README.md`;
  - `PROJECT_OVERVIEW.md`;
  - `CHANGELOG.md`;
  - `docs/versions/v1.5.2.md`.
- `.gitignore`, исключающий `OLED_series/` и локальные рабочие файлы.

### Изменено

- Версия приложения обновлена до `v1.5.2`.
- Для папок измерений используется нейминг вида `CR1/CR1_1/CR1_1_1`.
- Спектральная обработка использует raw-спектр.
- Фон спектра считается как среднее значение короткого плоского участка raw-спектра.
- `Dark corrected` оставлен как диагностический лист, но не участвует в основной обработке.

- После статуса `BURNED` запускается дополнительный подтверждающий цикл.
- При съёмке серии окно выбора ВАЯХ закрывается перед стартом.
- Выбор произвольного пикселя в режиме серии используется как стартовая точка.
- Большой круг с карты подложкодержателя убран.
